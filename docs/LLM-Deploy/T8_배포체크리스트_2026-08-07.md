## 2. 환경변수 (실키 전환)

로컬 저장소 `.env`의 `MOCK_LLM=true`는 **절대 바꾸지 않는다** (§4). 실키는 배포 환경 주입으로만.

| 변수 | 배포값 | 주의 |
|---|---|---|
| `MOCK_LLM` | `false` | |
| `MOCK_BACKEND` | `false` | |
| `OPENAI_API_KEY` | 실키 | |
| `BACKEND_BASE_URL` | 실 백엔드 주소 | 기본값 `http://localhost:8080`인 채 배포하면 콜백·조회 전부 실패 |
| `SERVICE_TOKEN` | **실토큰 필수** | 코드 기본값이 `dev-service-token-change-me` — 안 바꾸면 인증이 뚫린 것과 같다. 백엔드와 같은 값으로 |
| `DATABASE_URL` | (compose가 주입) | 이번 배포는 같은 VM의 `llm-postgres` 컨테이너다. compose의 `environment:`가 `…@llm-postgres:5432/…`로 덮어쓰므로 **`.env`에서 고쳐도 안 바뀐다** |
| `LANGSMITH_*` | 선택 | 켜면 `LANGSMITH_API_KEY` 필요 |
| `OPENBLAS_NUM_THREADS` | `1` | Dockerfile·compose에는 여전히 없지만 **`.env`에 넣으면 `env_file`로 api·worker 양쪽에 들어간다**(배포 절차서 §5-1이 이 방식). 넣고 시작하고, 실제 필요 여부는 배포 직후 context_refresh 잡으로 확인 |

- [ ] worker 프로세스에도 같은 env가 들어가는지 확인 — api·worker는 **별도 프로세스**다 (compose에서 entrypoint만 다름).
- [ ] **`.env`를 고친 뒤에는 `restart`가 아니라 재생성이다** — `env_file`은 컨테이너를 **만들 때** 읽히고 `get_settings()`는 `lru_cache`다. `docker compose restart`로는 반영되지 않는다. `docker compose up -d --force-recreate llm-api llm-worker` 후 `docker compose exec llm-api printenv BACKEND_BASE_URL`로 눈으로 확인할 것.
  - **`BACKEND_BASE_URL`을 나중에 채우는 절차에서 특히 위험하다** — 컨테이너는 `Up`으로 정상인데 지출 조회·콜백만 전부 실패한다. §4의 "첫 호출 무한 대기"를 0-1로 오진하기 쉬운 지점.
