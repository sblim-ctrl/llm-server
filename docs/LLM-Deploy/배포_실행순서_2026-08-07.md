# LLM 서버 배포 — 복붙 실행 순서

> 위에서부터 그대로 따라 하면 됩니다. **⚠️ 표시된 곳만 값을 직접 채우세요.**
> 풀스택팀 답변 없이 §1~§5까지 진행 가능합니다. §6만 주소를 받아야 합니다.

## §0. 준비물

- GCP 계정 (구글 계정으로 로그인, 신규는 무료 크레딧 $300 제공)
- OpenAI API 키 (실키)
- 저장소 접근 권한 (이미 있음)

## §1. VM 만들기 (웹 브라우저에서, 5분)

1. https://console.cloud.google.com 접속
2. 상단 검색창에 **`Compute Engine`** 입력 → 클릭
3. 처음이면 "Compute Engine API 사용 설정" 버튼이 뜹니다 → 누르고 1~2분 대기
4. **`인스턴스 만들기`** 클릭
5. 아래대로 설정:

| 항목 | 값 |
|---|---|
| 이름 | `llm-server` |
| 리전 | **`asia-northeast3 (서울)`** |
| 영역 | 아무거나 (a) |
| 머신 유형 | **`e2-medium`** (2 vCPU · 4GB) |
| 부팅 디스크 → 변경 | **Ubuntu 22.04 LTS**, 크기 **30GB** |
| 방화벽 | ☐ HTTP 허용 · ☐ HTTPS 허용 — **둘 다 체크하지 마세요** |

6. 맨 아래 **`만들기`** 클릭 → 1분쯤 후 목록에 초록색 체크가 뜹니다

> **왜 e2-medium인가**: 컨테이너 3개(API·워커·DB)를 동시에 돌리면서 이미지 빌드까지 해야 해서
> e2-small(2GB)로는 빠듯합니다. (회칙을 벡터로 바꾸는 계산 자체는 OpenAI API가 하므로 이 서버의
> 부담이 아닙니다 — `app/llm/client.py:187`.) 월 4만원 정도이고, 데모가 끝나고 인스턴스를
> 삭제하면 과금이 멈춥니다.

## §4. 코드 받기

```bash
git clone https://github.com/cowbrooo/llm-server.git
cd llm-server
```

비공개 저장소라 아이디·토큰을 물어보면:
- Username: GitHub 아이디
- Password: **비밀번호 말고 Personal Access Token**
  (GitHub → 우상단 프로필 → Settings → Developer settings →
   Personal access tokens → Tokens(classic) → Generate new token → `repo` 체크)

받았으면 어떤 코드인지 확인:

```bash
git log --oneline -1
```

**배포 기준 코드는 `ce18f7e`입니다** (PR #26, 배포 이미지에 scripts 포함까지 반영된 main).
이보다 최신이면 그대로 진행하고, 더 옛날 것이면 팀장에게 확인하세요.

### 4-1. DB 포트 닫기 (VM에서만, 30초)

받은 코드는 로컬 개발용이라 Postgres 5433 포트가 서버 바깥으로 열려 있습니다. VM에서는
같은 네트워크의 다른 서버가 `budgetops/budgetops`로 DB에 바로 붙을 수 있으니 닫습니다.

```bash
sed -i 's/^      - "5433:5432"/      - "127.0.0.1:5433:5432"/' docker-compose.yml
grep -n 5433 docker-compose.yml     # 127.0.0.1:5433:5432 로 바뀌었으면 성공
```

> 컨테이너끼리의 통신(API↔DB)은 이 설정과 무관해서 바꿔도 동작에 영향이 없습니다.

## §5. 설정하고 띄우기

### 5-1. `.env` 만들기

```bash
nano .env
```

아래를 붙여넣고 **⚠️ 세 곳**을 채웁니다:

```
# ── 실모드 전환 (배포에서는 반드시 false) ──
MOCK_LLM=false
MOCK_BACKEND=false

# ⚠️ OpenAI 실키
OPENAI_API_KEY=sk-여기에_실제_키

# ⚠️ 백엔드가 우리를 부를 때 쓸 인증 토큰.
#    아무 긴 문자열로 정하고, 그대로 백엔드팀에 알려주세요.
#    (기본값 dev-service-token-change-me 로 두면 /readyz가 실패합니다)
SERVICE_TOKEN=여기에_긴_임의_문자열

# ⚠️ 백엔드 주소 — 아직 모르면 이대로 두고 §6에서 채웁니다
BACKEND_BASE_URL=http://localhost:8080

# ── DB (아래 그대로 — 실제로는 compose가 같은 값을 덮어씁니다. 여기서 고쳐도 안 바뀝니다) ──
DATABASE_URL=postgresql://budgetops:budgetops@llm-postgres:5432/budgetops_llm

# ── 실모드 메모리 오류 방지 ──
OPENBLAS_NUM_THREADS=1

# ── 관측 (선택, 안 켜도 됨) ──
LANGSMITH_TRACING=false
```

저장: **`Ctrl+O` → `Enter` → `Ctrl+X`**

### 5-2. 띄우기

```bash
docker compose up -d --build
```

처음엔 이미지를 만드느라 **3~5분** 걸립니다.

### 5-3. 확인

```bash
docker compose ps
```

`llm-postgres` · `llm-api` · `llm-worker` **세 개가 모두 `Up`** 이어야 합니다.

```bash
curl localhost:8000/healthz
curl "localhost:8000/readyz?deep=true"
```

`readyz`가 200이면 **OpenAI 키까지 살아 있다는 뜻**입니다.

> **DB 테이블은 따로 만들 필요 없습니다.** API와 워커가 기동할 때 `apply_schema()`로
> 테이블·인덱스·pgvector 확장을 자동 생성합니다. 별도 마이그레이션 명령이 없습니다.

### 5-4. 안 될 때

```bash
docker compose logs llm-api --tail 50      # API 로그
docker compose logs llm-worker --tail 50   # 워커 로그
docker compose logs llm-postgres --tail 30 # DB 로그
```

| 증상 | 원인 |
|---|---|
| `readyz`가 503 | `.env`의 `SERVICE_TOKEN`이 기본값이거나 `OPENAI_API_KEY`가 비었음 |
| 컨테이너가 계속 재시작 | 로그 확인. 대개 `.env` 오타 |
| `permission denied` (docker) | §3의 재접속을 안 했음 |

**여기까지 되면 배포의 90%가 끝났습니다.**

## §6. 백엔드와 연결 (풀스택 답변 후 · 5분)

### 6-1. 백엔드 주소 넣기

```bash
nano .env      # BACKEND_BASE_URL 을 받은 주소로 수정
docker compose up -d --force-recreate llm-api llm-worker
```

> **⚠️ `docker compose restart`를 쓰면 안 됩니다.** `.env`는 컨테이너를 **만들 때** 읽힙니다.
> `restart`는 기존 컨테이너를 그대로 다시 켜기만 해서, 주소가 `localhost:8080`인 채로 남습니다.
> 컨테이너는 멀쩡히 `Up`으로 보이는데 지출 조회·콜백만 전부 실패하기 때문에 원인을 찾기가
> 아주 어렵습니다. 반드시 위처럼 재생성하세요.

반영됐는지 눈으로 확인:

```bash
docker compose exec llm-api printenv BACKEND_BASE_URL
```

### 6-2. 방화벽 규칙 만들기

백엔드가 AWS EC2(Elastic IP)로 재배포 중이라 우리와는 다른 클라우드입니다 — **항상 외부 IP +
방화벽 규칙 방식만 성립합니다.**

GCP 콘솔 → 검색창에 **`방화벽`** → `방화벽 규칙 만들기`

| 항목 | 값 |
|---|---|
| 이름 | `allow-llm-from-backend` |
| 대상 | 네트워크의 모든 인스턴스 |
| 소스 IPv4 범위 | **⚠️ 백엔드 IP** (예: `34.64.10.5/32` — 반드시 `/32`) |
| 프로토콜/포트 | TCP, **`8000`** |

> **`0.0.0.0/0`은 절대 넣지 마세요** — 인터넷 전체에 여는 것입니다.
> 우리 API는 토큰 인증이 있지만, 열어둘 이유가 없습니다.

### 6-3. 우리 주소 알려주기

인스턴스 목록의 **외부 IP**를 알려주세요. **6-2를 반드시 먼저** 하세요.

전달할 값 3개: **주소 · 포트(8000) · `SERVICE_TOKEN`**

### 6-4. 계약 검증

```bash
docker compose exec llm-api python scripts/verify_backend_contract.py \
  --base-url <백엔드주소> --token <SERVICE_TOKEN> \
  --team-id <실재하는 팀ID> --expense-id <실재하는 지출ID>
```

> `scripts/`는 PR #26으로 이미지에 포함됩니다(main `ce18f7e`). **§4의 기준 코드가 맞다면
> 위 명령이 그대로 동작합니다.** 혹시 `No such file or directory`가 나오면 그보다 옛날
> 코드를 받은 것이니 §4로 돌아가 확인하세요.

**⚠️ 팀ID·지출ID는 백엔드에 실제로 존재하는 값이어야 합니다.** 백엔드팀에 미리 받아 두세요 —
당일 이것 때문에 대기하는 일이 자주 생깁니다.

CRITICAL 실패가 뜨면 **여기서 멈추고** 백엔드팀에 알리세요 — 그 상태로는 심사가 시작되지 않습니다.

## 자주 쓰는 명령

```bash
cd ~/llm-server

docker compose ps                    # 상태 보기
docker compose logs -f llm-worker    # 로그 실시간 (Ctrl+C로 나감)
docker compose restart llm-api       # 단순 재시작 (⚠️ .env 수정은 이걸로 반영 안 됨)
docker compose down                  # 전부 내리기 (데이터는 남음)
docker compose up -d                 # 다시 올리기

# .env를 고친 뒤에는 반드시 이것 (§6-1)
docker compose up -d --force-recreate llm-api llm-worker

git pull && docker compose up -d --build   # 코드 갱신 후 재배포
```

> **`git pull`이 거부되면** (`Your local changes would be overwritten`) §4-1에서 고친
> `docker-compose.yml` 때문입니다. 이렇게 하세요:
> ```bash
> git stash && git pull && git stash pop
> ```

## 부록. VM 없이 먼저 연동을 시작해야 할 때 (정말 비상시에만 — 최후 수단)

백엔드가 AWS EC2 Elastic IP(고정 IP)로 확정되어, 이제는 §1~§6을 그대로 따라가면 정식
주소를 받을 수 있습니다. **아래는 VM이 도저히 제때 뜰 수 없는 정말 비상 상황에서만
쓰는 최후 수단입니다.** 로컬에서 스택을 띄우고 터널로 임시 주소를 줄 수 있습니다.
10~15분이면 됩니다.

```bash
# 로컬에서 실모드로 스택 기동
#  ⚠️ 저장소 .env의 MOCK_LLM=true는 건드리지 말고, §5-1 내용으로 별도 파일을 만들어 쓸 것
docker compose up -d --build

# 터널 열기 — 가입·계정 불필요. 실행하면 https 주소가 화면에 바로 나옵니다
cloudflared tunnel --url http://localhost:8000
```

- **방화벽·IP 협의가 필요 없습니다.** 백엔드 IP를 아직 못 받았거나, §6-2 방화벽 규칙을
  당장 만들기 어려운 상황에도 그대로 씁니다.
- 백엔드에 줄 것은 §6-3과 같습니다: **발급된 https 주소 · `SERVICE_TOKEN`**
  (포트는 주소에 포함되므로 따로 알릴 필요 없음)
- **한계**: 노트북을 켜 둬야 하고, 터널을 다시 실행하면 주소가 바뀝니다.
  **VM 배포를 대체하지 않습니다** — 임시로만 쓰고 VM이 뜨면 주소를 교체하세요.
- 반대 방향(우리 → 백엔드 지출 조회·콜백)은 우리 쪽에서 나가는 요청이라 터널이 필요 없습니다.
  백엔드 주소만 받아 `.env`에 넣으면 됩니다(§6-1).
