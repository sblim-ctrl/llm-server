# 회신 요청 사항

| 항목 | 내용 |
|---|---|
| 최종 갱신 | 2026-07-31 (16번 추가) |
| 함께 보는 문서 | `풀스택_연동_계약.md`(기술 계약) · `openapi.json`(엔드포인트 스펙) · `백엔드_요구_내부API_명세.md`(1번의 구체안) |

공유해 주신 API 명세서와 DB 테이블 스키마 잘 받았습니다. 저희 코드와 하나씩 맞춰본 결과
그동안 막혀 있던 다섯 가지가 풀렸습니다. 관리자 검토로 넘어간 건의 AI 소견을 어디 저장할지,
`escalationThreshold`가 금액이라는 것, 카테고리별 예산 한도는 없다는 것, 회칙 버전 관리 방식,
승인/반려를 백엔드에서 실행하신다는 것입니다. 저희 코드에 반영했습니다.

새로 확인이 필요해진 것을 급한 순서로 정리했습니다. 전부 데모 일정에 영향이 없는 항목이니
편하신 시점에 답 주시면 됩니다.

## A. 연동 필수 (1~3)

이 세 건이 해결되지 않으면 실제 연동을 시작할 수 없습니다.

### 1. 내부 조회 API 미등재 (R1)

심사를 하려면 저희가 백엔드에 여덟 가지를 되물어야 합니다. 지출 상세, 예산, 팀 설정, 모임 유형,
멤버 명단, 회칙 원문, 영수증 이미지, 관리자 결정 내역입니다. 받은 명세서(API-001~050)는 화면에서
쓰는 API만 담고 있어 이 여덟 가지가 없습니다.

내부용 API 명세를 따로 열어 주세요. 경로와 응답 필드만 정해 주시면 저희는 파일 한 곳만 바꾸면
됩니다. 저희 제안을 `백엔드_요구_내부API_명세.md`에 정리해 뒀습니다. 각 API의 경로·파라미터·
응답 예시와 우선순위(필수 6 / 권장 1 / 미사용예정 2), 실패 시 동작까지 담았습니다. 그대로
쓰셔도 되고 편한 형태로 바꾸셔도 됩니다.

### 2. API-045 응답 구조

지출 건마다 `ai_job_id`·`ai_dispatched_at` 컬럼을 두신 것을 보면 요청을 보내고 나중에 콜백을
받는 구조로 이해했습니다. 그렇다면 API-045가 응답하는 시점에는 아직 심사 결과가 없습니다.

접수만 하고 결과는 콜백으로 받는 구조가 맞을까요. 맞다면 명세서의 응답값 표기만 고치면 됩니다.

### 3. 카테고리 목록 불일치

지출 카테고리가 일곱 개(회의·IT_인프라·행사·교육·식비·디자인·기타)로 고정되어 있는데, 저희는
모임 유형별로 다른 카테고리를 씁니다. 스터디는 `교재/자료비`, 친목은 `숙박/여행비` 같은 식으로
유형당 여섯 개입니다. 교집합이 하나도 없어서, 저희가 추천한 값을 그대로 넣으면 저장이 실패합니다.

카테고리를 늘려 주실 수 있을까요. 지금 일곱 개는 회사 지출 위주라 동아리·친목·동호회에서 쓰는
숙박·대관·교통·장비·홍보가 전부 기타로 몰리고, 카테고리별 통계 화면의 의미도 약해집니다. 방법은
두 가지로 생각하고 있습니다. ① 유형별 대표 카테고리를 목록에 추가 ② 카테고리를 별도 테이블로
빼서 모임 유형별로 다르게 두기. 늘려 주시기 전까지 저희는 지금 목록을 유지하고 코드를 바꾸지
않겠습니다.

## B. 요구사항 미충족 (4~7)

동작은 하지만 의도한 결과가 나오지 않는 항목입니다.

### 4. 지출 등록 시 자동 승인 (Q1 재확인)

API-016 설명에 "팀 설정에 따라 등록 시점의 status가 SUBMITTED / ESCALATED / 승인됨 중 하나로
자동 결정"이라고 되어 있습니다. AI 심사를 거치지 않고 승인이 되면 AI가 함부로 승인하지 않도록
막는 장치가 무력화되고, AI 심사 자체의 의미가 없어집니다.

등록 시점에는 항상 `SUBMITTED`이고 승인은 저희 콜백을 받은 뒤에만 되는 구조가 맞을까요.
7월 15일에도 여쭤봤던 항목입니다.

### 5. escalationThreshold 조회·수정 경로 부재 (Q4③)

이 금액을 넘으면 무조건 관리자 검토로 보내는 값인데, DB에서는 필수값(NOT NULL)인 반면 팀 설정
조회(API-028)·수정(API-029) 어디에도 이 필드가 없습니다. 모임 생성(API-009) 응답에만 나옵니다.

공유해 주신 AI 마법사 2단계가 이 값을 관리자가 직접 정하는 화면이었습니다(관리자 확인 설정 금액,
10/20/30만원 프리셋). 화면 안내에도 "여기서 설정한 값은 에이전트 정책 화면에서 언제든 바꿀 수
있어요"라고 되어 있는데, 조회·수정 API에 필드가 없으면 그 화면이 동작하지 않습니다. 같은 화면의
"모든 지출 직접 확인할래요" 토글(`autoApprove`)도 마찬가지입니다.

조회·수정 API에 `escalationThreshold`·`autoApprove` 두 필드를 추가해 주시고, 모임 생성 시
설정을 생략하면 어떤 기본값이 들어가는지도 알려주세요.

### 6. 알림 문구에 AI 소견 미포함 (R5)

알림 문구를 조회 시점에 `expenses`·`users`만 조인해서 만드신다고 되어 있는데, AI 소견은
`audit_logs`에 저장되기 때문에 왜 관리자 검토로 넘어갔는지를 알림에 넣을 수가 없습니다.

알림 문구를 만드실 때 `audit_logs`도 함께 조인해 주실 수 있을까요.

### 7. 회칙 변경 통지 부재

회칙을 등록(API-031)하거나 수정(API-033)하셨을 때 저희에게 알려주는 호출이 명세에 없습니다.
저희는 회칙을 미리 읽어두고 심사하기 때문에, 통지를 못 받으면 계속 이전 회칙으로 심사하게 됩니다.

AI 마법사 3단계가 회칙을 등록하는 화면(파일 업로드·직접 입력)이라 이 항목의 우선순위가
올라갔습니다. 지금 상태로는 관리자가 마법사에서 회칙을 등록하고 설정 완료까지 눌러도 그 회칙이
심사에 반영되지 않습니다.

회칙이 바뀔 때 저희 쪽에 `{teamId, 변경유형, 버전}` 세 가지만 보내주시면 됩니다
(`POST /v1/context/refresh`). 원문은 저희가 다시 조회하겠습니다.

덧붙여 API-046(심사 결과 조회)에 "관리자 검토 대기 중에는 결과가 비어서 404를 줄지 null을 줄지
확인 필요"라고 적어두셨는데, 그 경우 소견은 API-022(처리 이력)에서 보이므로 API-046은 null로
고정하시는 편이 프론트에서 단순할 것 같습니다.

## C. 운영 규모·개인정보 (8~10)

LLM팀에서 새로 제기하는 항목입니다.

### 8. 심사 제한 시간과 동시 요청량

`bravo 기술아키텍처설계서`에 "일정 시간(예: 30초) 안에 콜백이 오지 않으면 자동으로 ESCALATED로
전환한다"고 되어 있는데 30초가 확정치인지 불명확합니다. 저희 실측치를 먼저 공유드립니다
(2026-07-28, 실모드 9건 · 골든셋 표본).

| 구간 | 소요 |
|---|---|
| 큐 대기 (워커 폴링 2초 주기) | 최대 2.0초 |
| 심사 그래프 실행 | 중앙값 3.3초 / 최대 4.4초 |
| 콜백 HTTP 왕복 | 수백 ms |
| 단건 합계(추정) | 약 5~7초 |

단건 기준으로는 30초 예산에 충분히 들어갑니다. 최악 케이스도 약 25초 여유가 있습니다. 영수증
금액이 신청과 다른 건은 LLM 호출 없이 0.4초에 조기 종료됩니다.

다만 동시에 몰리면 초과합니다. 현재 워커는 1대가 1건씩 순차 처리해서 큐에 쌓이면 대기가
누적됩니다.

| 큐 순번 | 대기 | 심사 | 합계 | 30초 |
|---|---|---|---|---|
| 5번째 | 16초 | 4초 | 20초 | 여유 |
| 7번째 | 24초 | 4초 | 28초 | 임계 |
| 8번째 | 28초 | 4초 | 32초 | 초과 |

워커 대수를 늘리면 비례해 해소되는 구조라(중복 처리 없음), 예상 동시 요청량만 알려 주시면
대수를 맞추겠습니다.

회신 부탁드립니다.

1. 확정된 제한 시간은 몇 초입니까.
2. 동시 심사 요청이 최대 몇 건까지 예상됩니까. (동시 20건이면 워커 3대로 맞추겠습니다)
3. 제한 시간을 넘겨 도착한 콜백은 폐기됩니까, 상태 전이 없이 소견만 저장됩니까.

위 실측에 영수증 이미지 OCR은 포함하지 않았습니다(텍스트 변환 기준). 실이미지 심사는 Vision
호출이 추가돼 2~5초 더 걸릴 것으로 봅니다.

### 9. 콜백 판정 필드명과 값 형식

현재 저희는 `verdict` 키에 `approve` / `reject` / `escalate`를 소문자로 보냅니다. 명세서
API-045/046의 응답 필드는 `finalVerdict`입니다. 명세서의 상태값은 `SUBMITTED`/`ESCALATED`/
`APPROVED`/`REJECTED`로 대문자인데, `finalVerdict`의 값 형식은 명시되어 있지 않습니다.

① 콜백 키를 `finalVerdict`로 바꿀까요. 백엔드에서 이미 `verdict`로 매핑 중이면 현행을
유지하겠습니다. ② 값은 대문자입니까 소문자입니까. ③ 저희 `escalate`는 status `ESCALATED`와
1:1 대응입니까.

### 10. detail 필드 구성과 요청자 노출 범위

API-045/046 응답의 `review.detail`은 단일 문자열인데, 저희는 재료를 세 가지로 나눠서 보냅니다.

| 저희가 보내는 것 | 성격 |
|---|---|
| `reasons.requester` | 요청자용. 정중한 문체이며 금액·한도 등 수치를 넣지 않습니다 |
| `reasons.admin` | 관리자용. 회칙 조항과 수치를 인용합니다 |
| `opinions[]` | 심사관 3종(회칙·예산·판례)의 소견 원본 |

① `detail`은 백엔드에서 위 재료로 조합하십니까, 저희가 완성된 문자열로 보내야 합니까.
② `detail`이 지출 신청자에게도 보이는 화면이 있습니까. 있다면 `reasons.admin`의 수치가
신청자에게 노출되지 않도록 저희가 필드를 분리해 보내야 합니다. 개인정보 관련 사항이라 확인
부탁드립니다.

## D. 표기·형식 정합 (11~16)

기능 영향은 작고, 서로 어긋난 부분을 맞추는 항목입니다.

### 11. API-044 응답 형식 불일치 (R6)

저희가 내려주는 것은 조항 목록, 추천 승인기준(자동승인 한도 등), 추천 카테고리인데, 명세의
응답은 `{제목, 등록방식, 내용}` 형태라 추천 승인기준을 담을 자리가 없습니다.

`teamId` 문제는 화면 설계를 보고 저희 쪽에서 정리했으므로 답 주지 않으셔도 됩니다. 모임 생성
화면에서 "모임 만들고 설정 시작하기"를 누른 뒤 마법사로 들어가는 흐름이라, 마법사 진입 시점에는
이미 `teamId`가 있습니다. 3단계 회칙 등록도 `teamId` 없이는 불가능하니 앞뒤가 맞습니다. 저희
`/v1/policy-draft`는 `teamId`를 받지 않으므로, API-044에서 `teamId`로 팀을 조회하신 뒤
`teamType`·`teamName`·`initialBudget`·모임 소개로 변환해 저희를 호출해 주시면 됩니다. 저희가
예전에 드렸던 teamId 없이 호출해 달라는 요청은 철회합니다.

남은 두 가지만 확인 부탁드립니다. ② 추천 승인기준은 버리는 건지, 팀 설정 수정(API-029)으로
따로 넣으시는 건지 ③ 모임 초기 예산 컬럼을 `teams`에서 빼셨는데 저희는 초안을 만들 때 그 금액이
필요합니다. 예산 테이블에서 꺼내주시면 될까요.

### 12. 대시보드 AI 요약 방식 (API-024)

저희는 이 기능을 다음 스프린트로 미뤄뒀는데 명세에 정식으로 들어가 있어 다시 잡았습니다.

백엔드에서 집계한 숫자를 넘겨주시고 문구만 받으시는 방식이면, 저희가 그에 맞는 API를 새로
만들겠습니다. 넘겨주실 집계 항목 목록만 알려주세요. 정산 리포트 요약도 같은 방식으로 갈지 함께
정하면 좋겠습니다.

### 13. 명세서 내부 불일치 2건

① `audit_logs`의 `event_type` 목록에 값이 비어 있는 자리가 하나 있고, 설명에는 `EDITED`가
언급되는데 목록에는 없습니다. AI 심사가 끝나 소견을 저장했다는 이벤트도 없어서, 저희 콜백이
도착했을 때 어떤 값으로 기록되는지 알 수 없습니다. ② 모임 초기 예산이 DB(`teams`)에서는 빠졌는데
API-009 요청·응답에는 그대로 남아 있습니다. 11번 ③과 같은 건입니다.

`event_type` 목록을 확정해 주세요.

### 14. 필드 표기 혼용

① 심사 요청(`POST /v1/analyze`)은 받을 때는 `jobId`처럼 camelCase인데 응답은 `job_id`처럼
snake_case입니다. `GET /v1/jobs/{id}` 응답도 같습니다. ② 콜백은 최상위가 전부 camelCase인데
`opinions[].similar_cases` 하나만 snake_case로 나갑니다.

저희 판단으로는 전부 camelCase로 통일하는 것이 자연스러운데, 백엔드 파서에 이미 반영하신 것이
있으면 그 기준을 알려주세요. 저희는 파일 한두 곳만 고치면 됩니다. 임의로 바꾸면 계약이 또
어긋나므로 현상 그대로 전달드립니다. 상세 예시는 `풀스택_연동_계약.md` 4절에 있습니다.

### 15. 모임 생성·AI 마법사 화면 대조

화면 설계 4장(모임 생성, 마법사 1~3단계) 잘 받았습니다. 저희 `POST /v1/policy-draft`와 하나씩
맞춰본 결과입니다. 모임 유형 5종, 모임 이름, 모임 소개, 카테고리 자동 추천은 그대로 맞습니다.
아래 여섯 가지만 확인 부탁드립니다.

**① 회비 금액 전달 (1단계)**

화면 설명이 "AI가 예산 심사 시 기준으로 활용해요"인데, 지금까지 저희가 받는 금액은 초기 예산
하나뿐이었습니다. 저희 쪽에 `dues`(1인당 회비) 필드를 이미 열어 뒀으니(`openapi.json`의
`PolicyDraftRequest` 참조) API-044 요청에 실어 주시기만 하면 됩니다. 안 보내주셔도 지금처럼
동작합니다. 저희는 이 값을 회칙 초안의 회비 조항에 씁니다. 화면의 "없음" 체크는 `null`과 `0`
둘 다 없음으로 처리하도록 해뒀으니 편한 쪽으로 보내주시고, 어느 쪽으로 보내실지만 알려주세요.

회비를 자동승인 한도 계산에는 넣지 않았습니다. 회비는 1인당 금액인데 인원 수를 받는 경로가
없어서(②번) 총액으로 환산할 수가 없고, 그 상태로 한도 공식에 넣으면 근거 없는 규칙을 저희가
임의로 만드는 셈이 됩니다. 인원 수 문제가 정리되면 반영하겠습니다.

**② 무료 플랜 20명 제한의 검증 주체**

저희 요청 스키마에 `memberCount`라는 선택 필드가 있지만 상한 검증이 없고, 모임 생성 화면에
인원을 입력하는 칸이 없어 이 값을 어디서 받아야 할지 모르겠습니다. 정원 제한은 플랜·과금 쪽이라
백엔드에서 보시는 것이 맞을 것 같은데, 맞다면 저희는 이 필드를 비워두고 쓰겠습니다.

**③ 모임 이름·초기 예산의 필수 여부**

모임 생성 화면에는 필수 표시(`*`)가 모임 유형에만 붙어 있는데, 저희 API는 모임 이름과 초기
예산도 필수이고 초기 예산은 0보다 커야 합니다. 화면대로 비운 채 넘어오면 저희가 422로 거절하게
됩니다. 화면에 필수 표시를 맞춰 주시거나 저희 쪽을 선택값으로 푸는 방법이 있는데, 어느 쪽이
좋을지 알려주세요. 11번 ③의 초기 예산 조달 경로와 같은 건입니다.

**④ 고액 기준 200,000원 (2단계)**

저희는 자동승인 한도의 6배를 강제 관리자 검토 금액으로 제안하고 있어서, 소액 기준이 5만원이면
고액 기준은 30만원이 나왔습니다. 화면 표(소액 5만 미만 / 중간 5~20만 / 고액 20만 이상)에
맞추려면 6배가 아니라 4배여야 해서, 저희 계산을 4배로 바꾸고 코드 기본값도 300,000원에서
200,000원으로 내렸습니다. 이제 초기예산 100만원짜리 모임이면 화면 표와 같은 5만/20만이 나옵니다.
백엔드 `escalationThreshold`의 기본값도 200,000원으로 잡으실지만 알려주세요.

**⑤ 중간 지출 "대기/자동"의 의미 (2단계)**

표의 소액·고액은 저희 금액 기준과 1:1로 맞는데, 중간 구간만 저희 쪽에 대응하는 개념이 없습니다.
저희는 이 구간을 금액이 아니라 AI 확신도(기본 0.8)로 가릅니다. 확신하면 자동, 아니면 관리자
대기입니다. 화면 문구가 그 뜻이면 저희는 바꿀 것이 없습니다.

**⑥ "건너뛰기 → 기본 정책 모드"의 정의 (3단계)**

회칙 없이 심사하게 되는 경우인데 저희 쪽에 정의가 없습니다. 저희가 갖고 있는 모임 유형별 기본
조항(영수증 필수, 1인당 식비 한도 등)을 적용한다는 뜻으로 이해하면 될까요. 정해 주시면 저희가
그 동작을 명시적으로 구현하겠습니다. (16번 ②에 구현 결과를 적었습니다)

화면 안에서 단계 순서가 서로 다르게 그려져 있습니다. 1·3단계 상단은 `회비·예산 → 회칙·규정 →
승인 정책`인데 2단계 상단은 `회비·예산 → 승인 정책 → 회칙·규정`이고, 2단계에 "설정 완료",
3단계에 "다음" 버튼이 붙어 있어 어느 쪽이 마지막인지 알기 어렵습니다. 저희 계약에는 영향이
없지만 회칙 등록이 몇 번째인지에 따라 7번의 통지 시점이 달라지므로, 확정되면 알려주세요.

### 16. 프로토타입 확인 결과 (15번 후속)

공유해 주신 Figma 프로토타입에서 모임 생성과 마법사 1~3단계 화면 네 장을 직접 확인했습니다
(7/38, 8/38, 9/38, 10/38). 15번은 화면 이미지만 보고 쓴 것이라, 실물에서 새로 확인한 것과
그사이 저희가 반영한 것을 정리합니다.

15번 중 ②(20명 제한), ③(필수 표시), ⑤(중간 구간), 단계 순서는 그대로 답을 기다리고 있습니다.
③은 화면대로 이름·예산을 비워 보내시면 저희가 실제로 422로 거절하게 되니 상대적으로 급합니다.

**① 1단계 회비 안내 문구 수정 요청**

1단계 화면 부제가 "AI가 예산 심사 시 기준으로 활용해요"인데, 저희는 회비를 회칙 초안에만 쓰고
지출 심사에는 쓰지 않습니다(15번 ①에서 말씀드린 대로입니다). 지금 문구대로면 사용자는 회비를
넣으면 AI가 심사할 때 참고한다고 이해하는데 실제로는 그렇지 않아, 화면이 하지 않는 일을
약속하는 상태입니다.

"AI가 회칙 초안을 만들 때 반영해요" 정도로 고쳐 주실 수 있을까요. 심사에까지 반영하는 방향도
가능합니다만, 그러려면 내부 조회 API ③(예산 현황)에 회비 필드를 추가로 요청드려야 해서 범위가
커집니다. 필요하시면 말씀해 주세요.

**② 기본 정책 모드 구현 (15번 ⑥ 후속)**

15번 ⑥에서 뜻을 여쭀던 항목인데, 3단계 화면에 "나중에 등록해도 돼요. 없으면 기본 정책 모드로
시작해요"라고 명시돼 있어 먼저 구현했습니다. 이견 있으시면 알려 주세요.

회칙을 등록하지 않은 팀도 회칙 축 심사를 받되, 반려는 되지 않습니다.

| 항목 | 처리 |
|---|---|
| 근거 | 저희가 가진 모임 유형별 기본 조항 (영수증 첨부, 개인 용도 물품, 목적 무관 지출 등) |
| 금액 한도 조항 | 근거에서 제외했습니다 |
| 결과 | 어긋나면 관리자 확인(보류)으로 보냅니다. 자동 반려는 하지 않습니다 |

금액 조항을 뺀 이유는 두 가지입니다. 첫째, 금액은 이미 자동승인 한도와 고액 기준이 보고 있어
또 보면 같은 잣대를 두 번 대는 셈입니다. 둘째, 저희 템플릿의 금액(예: 1인당 식비 3만원)은 저희가
모임 유형만 보고 정한 값이라 그 모임이 동의한 적이 없습니다. 동의한 적 없는 금액으로 지출을
반려하면 관리자가 납득하기 어렵고, 화면의 "나중에 등록해도 돼요"라는 안내와도 어긋납니다.

회칙을 건너뛴 팀도 AI가 아무것도 보지 않는 상태는 아니게 됩니다. 다만 판단은 항상 관리자에게
넘어갑니다.

**③ autoApprove 추천값 추가 (계약 변경 통보)**

2단계 토글("당연히 모든 지출을 직접 확인할래요")에 대응하는 값을 저희가 내려드릴 통로가
없었습니다. `PolicyParamsSuggestion`에 `auto_approve`(boolean)를 추가했습니다. 회비(`dues`)
때와 같은 성격의 추가라 알려 드립니다. 안 쓰셔도 기존 동작 그대로입니다.

기본값은 `true`(AI 자동 심사 사용)로 잡았습니다. 프로토타입 2단계에서 그 토글이 꺼진 상태이고
구간표의 "소액 지출 → AI 자동 승인"이 켜진 것으로 표시돼 있어서입니다.

화면 토글의 기본 상태가 꺼짐이 맞는지만 확인해 주세요. 문구("직접 확인할래요")와 값
(`autoApprove`)이 서로 반대 방향이라 혼동하기 쉬운 지점입니다. 토글을 켜면 `autoApprove`는
`false`입니다.

**④ 소액 기준의 산출 방식 (고정값 아님)**

2단계 구간표가 "소액 지출 50,000원 미만"으로 적혀 있는데, 저희 자동승인 한도는 고정값이 아니라
초기 예산에 모임 유형별 비율을 곱해 계산합니다.

| 모임 | 계산 | 소액 기준 |
|---|---|---|
| 동아리, 초기예산 100만 | 100만 × 5% | 50,000원 (화면과 일치) |
| 스터디, 초기예산 60만 | 60만 × 5% | 30,000원 |
| 동호회, 초기예산 50만 | 50만 × 5%, 만원 단위 내림 | 20,000원 |
| 회사, 초기예산 300만 | 300만 × 3% | 90,000원 |

화면 예시가 마침 100만원 기준이라 5만원으로 맞았을 뿐, 예산이 다르면 다른 값이 나옵니다.

구간표 숫자가 저희가 내려드린 값으로 바뀌는 것이 맞는지, 아니면 화면은 5만원 고정 안내인지
알려 주세요. 고정이라면 사용자가 보는 기준과 실제 심사 기준이 달라집니다.

**⑤ 고액 기준과 프리셋 범위 (15번 ④ 후속)**

2단계에 프리셋 버튼 세 개와 직접 입력 칸이 함께 있는 것을 확인했습니다. 저희는 고액 기준을
자동승인 한도의 4배로 계산해 추천하는데, 이 값이 프리셋에 없을 수 있습니다. 동아리 초기예산
100만이면 5만 × 4 = 20만원으로 프리셋에 있지만, 회사 초기예산 300만이면 9만 × 4 = 36만원이라
프리셋에 없습니다.

저희 추천값을 직접 입력 칸의 초기값으로 넣어 주시면 그대로 표현됩니다. 그렇게 하실지, 아니면
화면은 항상 20만원으로 시작하고 저희 추천은 참고만 하실지 알려 주세요.
