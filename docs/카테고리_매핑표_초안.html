지출 카테고리 매핑표 초안

TL;DR — 카테고리 ENUM을 확장하지 않고 매핑으로 맞추는 방향, 받아들이겠습니다. 다만 보내주신 매핑표 6종은 저희 모임 유형 5종 중 동아리/학생회 하나의 목록입니다.
  • 저희 추천 카테고리는 모임 유형별로 다릅니다 — 유형당 6개 × 5유형 = 30종
  • 나머지 4유형 24종의 매핑을 아래에 제안드립니다. 확정만 해주시면 됩니다
  • 회신에 IT인프라는 매핑 대상이 아니라고 하셨는데, 회사 유형의 업무도구/소프트웨어비가 여기에 해당합니다
  • suggestedCategory 표기는 아직 확정이 안 됩니다 — 화면의 강연비와 7종 ENUM이 서로 맞지 않습니다 (7번 항목)

1. 배경 — 저희 카테고리가 30종인 이유

저희는 카테고리를 하나의 고정 목록으로 두지 않고 모임 유형마다 다른 6개를 씁니다. 같은 "회식 저녁"이라도 친목 모임이면 식비/모임비, 회사면 식대/회식비, 동호회면 식비/간식비로 분류됩니다. 유형 5종 × 6개 = 총 30종입니다.

이 목록은 두 곳에서 나갑니다. 마법사 1단계의 카테고리 자동 추천 (POST /v1/policy-draft 응답의 recommended_categories)과, 심사 콜백의 suggestedCategory입니다. 둘 다 같은 카탈로그를 씁니다.

★
보내주신 6종(행사/프로그램비 · 홍보/콘텐츠비 · 교육/강연비 · 식비/간식비 · 회의/운영비 · 물품/소모품비)은 저희 동아리/학생회 유형의 목록과 정확히 일치합니다. 스터디·친목·동호회·회사 유형은 전혀 다른 6개를 씁니다.

2. 매핑 원칙 — 주신 6종에서 역산했습니다

나머지 24종을 임의로 붙이면 검토가 어려우실 것 같아, 보내주신 6종이 따르는 규칙을 먼저 추출한 뒤 같은 규칙으로 24종을 붙였습니다. 표의 각 행에 어느 규칙을 적용했는지 번호로 표기했습니다.

규칙내용보내주신 6종의 예
① 이름 직접 대응 — 카테고리 이름 앞부분이 ENUM 값과 그대로 같음 행사/프로그램비 → 행사
② 산출물·목적이 한 ENUM에 명확히 속함 — 이름은 다르나 성격이 하나로 모임 홍보/콘텐츠비 → 디자인
③ 대응 ENUM 없음 → 기타 물품/소모품비 → 기타

규칙 ②는 6종 중 홍보/콘텐츠비 하나뿐이고, 그래서 풀스택 팀에서도 "한 번 더 검토 후 확정하겠다"고 하신 것으로 이해했습니다. 저희가 새로 제안하는 24종에서도 ②를 적용한 곳이 판단이 갈릴 수 있는 지점이라, 4번 항목에 따로 모아 두었습니다.

4. 확정이 필요한 4건

위 24종 중 아래 넷은 저희가 한쪽으로 정한 것이지 자명하지 않습니다. 판단 근거와 반대쪽 선택지를 같이 적었으니, 편한 쪽으로 정해 주시면 그대로 맞추겠습니다.

카테고리저희 제안 / 대안판단 근거와 반대 논거
온라인/구독비
스터디		 교육 / IT인프라 분류 키워드에 인강·수강·강의와 구독·멤버십·클라우드가 섞여 있습니다. 스터디 맥락에서는 강의 구독이 주류라 교육을 골랐고, 클라우드성 지출은 회사 유형의 업무도구/소프트웨어비가 더 정확한 수신처라고 봤습니다.
실습/프로젝트비
스터디		 IT인프라 / 기타 키워드가 실습·프로젝트·서버·도메인·API·재료·키트입니다. 개발 스터디를 전제로 IT인프라를 골랐지만, 비개발 스터디라면 재료·키트가 주가 되어 기타가 맞습니다.
활동/프로그램비
동호회		 교육 / 행사 이름은 "프로그램"이라 행사 쪽으로 보이지만, 키워드 5개 중 3개가 레슨·클래스·강습입니다. 동호회 실지출은 강습비 비중이 커서 교육을 골랐습니다.
공간/대관비 vs
장소/예약비		 회의 vs 기타 비슷해 보이는데 다르게 보낸 이유는 키워드 차이입니다 — 스터디는 스터디룸·회의실·공간, 친목은 파티룸·룸카페·장소입니다. "둘 다 기타"로 통일하셔도 저희는 무방합니다.

5. 이 매핑의 귀결 — 숫자로 보시면

30행을 ENUM 기준으로 뒤집어 세면 이렇게 됩니다. 매핑 승인 판단에 필요한 수치라 같이 드립니다.

30행 기준. 이름 기준(중복 교통비·식비/간식비 각 1회로 셈)으로는 28개이고, 그중 기타가 11개입니다.

친목 모임은 카테고리별 통계 화면이 거의 동작하지 않게 됩니다. 숙박·레저·선물·장소·교통이 모두 기타 한 칸에 들어가고 식비만 따로 잡힙니다.

회신요청 3번에서 저희가 말씀드렸던 "숙박·대관·교통·장비·홍보가 전부 기타로 몰린다"의 실제 수치입니다. 매핑으로 연동은 되지만 이 문제 자체가 해소되지는 않는다는 점만 공유드립니다 — ENUM 확장을 다시 요청드리는 것은 아니고, 나중에 통계 화면 요구가 올라올 때 참고하시라는 뜻입니다.

한 가지 더, 디자인 ENUM은 수신처가 홍보/콘텐츠비 하나뿐입니다. 재검토 끝에 이 매핑을 취소하시면 디자인 ENUM으로 오는 카테고리가 아예 없어집니다. 7번의 회신 요청에 포함했습니다.

6. 구현 — 유형별 표가 아니라 평면 표 28행이면 됩니다

30행이지만 이름 기준으로는 28개입니다. 교통비(친목·동호회)와 식비/간식비(동아리·동호회)가 중복인데, 둘 다 모임 유형과 무관하게 같은 ENUM으로 갑니다.

따라서 모임유형 × 카테고리 2차원 표를 만드실 필요가 없습니다. 카테고리 이름 하나당 ENUM 하나짜리 평면 표로 충분합니다. 바로 쓰실 수 있게 아래에 붙여 둡니다.

  -- IT인프라
  WHEN '업무도구/소프트웨어비' THEN 'IT인프라'
  WHEN '실습/프로젝트비'       THEN 'IT인프라' -- 확정 필요
  -- 디자인
  WHEN '홍보/콘텐츠비'         THEN '디자인'    -- 재검토 중
  -- 기타 (나머지 11종) — 명시하지 않고 ELSE로 받으셔도 됩니다
  ELSE '기타'
END
★

모르는 값이 오면 기타로 떨어뜨려 주세요. 저희 카탈로그는 팀 확정 사항이라 임의로 늘리지 않지만, 만에 하나 목록 밖 값이 가더라도 저장이 실패하지 않게 ELSE '기타' 형태를 권합니다.

ENUM 저장값 표기 한 가지만 확인 부탁드립니다. 위 표와 코드에는 8/4 회신에 적어주신 대로 IT인프라로 적었는데, 저희가 7/27에 받은 DB 스키마에는 IT_인프라(언더바)로 되어 있고 화면에는 IT/인프라(슬래시)로 표시됩니다. 저장값이 셋 중 어느 것인지만 알려주시면 그대로 맞추겠습니다 — 이 값 하나가 어긋나면 매핑이 통째로 실패합니다.

7. 회신 요청 3건

① 24종 매핑 승인 + 확정이 필요한 4건

3번 표의 신규 제안 24종을 그대로 쓰셔도 되는지, 그리고 4번의 네 항목을 어느 쪽으로 정하실지 알려주세요. 어느 쪽이든 저희는 값을 바꿔 보내는 게 아니라 표만 맞추면 되는 일이라 부담 없습니다.

② 홍보/콘텐츠비 → 디자인 재검토 결과

"한 번 더 검토 후 확정하겠다"고 하신 항목입니다. 이 매핑을 취소하시면 디자인 ENUM으로 오는 카테고리가 하나도 없게 됩니다(5번 차트 참조). 그 경우 홍보물 제작비를 어디로 보낼지도 같이 정해 주시면 좋겠습니다.

③ 콜백 suggestedCategory는 어느 목록을 따를까요 — 화면과 어긋나는 부분이 있습니다

"콜백 suggestedCategory도 이 표기로 주시면 바로 매핑됩니다"를 저희 쪽에서 두 가지로 읽었습니다. (가) 7종 ENUM 값 자체를 달라 (나) 저희 30종을 언더바 표기로만 바꿔 달라.

확정을 못 한 이유는 화면 설계와 7종 ENUM이 서로 맞지 않기 때문입니다. 지출 상세 화면 4종을 보면 카테고리와 자동 분류가 나란히 따로 표시되고, 강연료 건은 두 값이 서로 다릅니다.

(가)로 구현하면 화면의 강연비를 재현할 수 없습니다. 카테고리 칸과 자동 분류 칸이 늘 같은 값이 되어 자동 분류 칸이 무의미해집니다. 반대로 (나)라면 저희 동아리/학생회 교육/강연비가 화면의 강연비에 대응해 자연스럽습니다.

→ 자동 분류 칸이 따르는 목록을 알려주세요. 저희 30종이면 지금 값을 언더바로만 바꿔 보내겠고, 7종이면 저희가 위 매핑표를 적용해 ENUM 값으로 변환해 보내겠습니다. 별도 목록이 있으면 그 목록을 주시면 됩니다. (회신요청 16번 ⑥와 같은 건입니다)

★
덧붙여, ③과 맞물린 항목이 하나 있습니다. 풀스택 팀 expenses.category가 NOT NULL이라 저희가 지출 상세를 조회하면 카테고리가 항상 채워져 옵니다. 저희는 지금 카테고리가 비어 있을 때만 자동 분류를 돌리게 되어 있어서, 이대로면 suggestedCategory가 받은 값을 그대로 돌려주는 형태가 됩니다. 화면대로 두 칸이 서로 다른 값을 보여주는 게 맞다면 저희가 항상 분류하도록 고치겠습니다 — ③ 회신과 함께 알려주시면 한 번에 반영하겠습니다.
