# LLM 서버 연동 안내

BudgetOps LLM 서버 연동에 필요한 문서는 다섯 개입니다. 아래 순서로 보시면 됩니다.

| 순서 | 문서 | 내용 |
|---|---|---|
| 1 | [풀스택_연동_계약.md](풀스택_연동_계약.md) | 인증 방식, 비동기 심사 흐름, 콜백 페이로드 전문과 예시 |
| 2 | [openapi.json](openapi.json) | 엔드포인트 전체의 요청·응답 스키마. 코드에서 자동 생성하며 이 파일이 계약 기준입니다 |
| 3 | [마법사_API_명세.md](마법사_API_명세.md) | 모임 생성·AI 마법사 1~3단계에서 쓰는 API 4종. 화면별로 어느 API가 필요한지 정리했습니다 |
| 4 | [백엔드_요구_내부API_명세.md](백엔드_요구_내부API_명세.md) | 백엔드에 요청드리는 내부 조회 API 8종의 경로·파라미터·응답 예시. 회신요청 1번의 구체안입니다 |
| 5 | [풀스택_회신요청.md](풀스택_회신요청.md) | 확인·회신이 필요한 16건. 급한 순서로 정렬했습니다 |

공유해 드린 Swagger 링크(`/docs`)와 `openapi.json`은 내용이 다를 수 있습니다. 링크는 개발
서버가 그 시점에 실행 중인 코드를 그대로 보여주기 때문에, 코드를 고쳐도 재시작 전까지는
이전 내용이 뜨고 MVP에서 제외한 엔드포인트가 남아 보이기도 합니다. 계약 기준은 이 저장소의
`openapi.json`이며 링크는 동작 확인용으로 봐주시면 됩니다. 두 쪽이 어긋나 보이면 알려주세요.

## 연동 방식

심사는 비동기로 처리합니다. 요청은 접수만 하고 202로 즉시 응답하며, 결과는 심사가 끝난 뒤
콜백으로 보냅니다.

```
[백엔드]  POST /v1/analyze          ──►  [LLM 서버]   접수 후 202 즉시 응답
[백엔드]  POST /agent-callback      ◄──  [LLM 서버]   심사 완료 시 결과 발신
[백엔드]  GET  /v1/jobs/{job_id}    ──►  [LLM 서버]   폴링 fallback (콜백 유실 대비)
```

콜백 수신 엔드포인트(`POST /agent-callback`)는 백엔드에서 만들어 주셔야 합니다.

모든 요청에 `Authorization: Bearer <SERVICE_TOKEN>` 헤더가 필요합니다. `/healthz`,
`/readyz`, `/docs`, `/ui`는 예외입니다.

심사 요청에는 `jobId`, `expenseId`, `organizationId` 등 5개 필드만 담으시면 됩니다. 지출
상세·예산·회칙은 저희가 백엔드 내부 API로 되물어 조회합니다(pull 모델). 따라서 문서 3번의
API가 열리지 않으면 심사를 시작할 수 없습니다.

## 회신 요청

먼저 답변이 필요한 세 건입니다.

| # | 내용 |
|---|---|
| 1 | 내부 조회 API 8종 개설 (문서 3번에 제안 있음) |
| 2 | AI 심사 API(API-045)가 접수만 하고 콜백으로 결과를 받는 구조가 맞는지 확인 |
| 3 | 카테고리 목록이 저희 카탈로그와 교집합이 없어 확장 가능한지 확인 |

나머지 13건은 `풀스택_회신요청.md`에 급한 순서로 정리했습니다. 15·16번은 모임 생성과
AI 마법사 화면을 저희 API와 대조한 결과입니다. 전부 데모 일정에 영향이 없는 항목이니
편하신 시점에 답 주시면 됩니다.
