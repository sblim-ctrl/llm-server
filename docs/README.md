## 30초 요약

**심사는 비동기입니다.** 요청은 접수만 하고 202로 즉시 응답하며, 결과는 나중에 저희가
콜백으로 보냅니다.

```
[백엔드]  POST /v1/analyze          ──►  [LLM 서버]   접수 후 202 즉시 응답
[백엔드]  POST /agent-callback      ◄──  [LLM 서버]   심사 완료 시 결과 발신
                                                     ★ 이 수신 엔드포인트가 필요합니다
[백엔드]  GET  /v1/jobs/{job_id}    ──►  [LLM 서버]   폴링 fallback (콜백 유실 대비)
```

**모든 요청에 인증이 필요합니다** — `Authorization: Bearer <SERVICE_TOKEN>`
(면제는 `/healthz` · `/readyz` · `/docs` · `/redoc` · `/openapi.json` · `/ui` 6개뿐 —
문서 1번 §1 참조)

**저희도 백엔드를 호출합니다.** 심사 요청에는 `jobId`·`expenseId`·`organizationId` 등
5필드만 담으시면 되고, 지출 상세·예산·회칙은 저희가 내부 API로 되물어 가져옵니다(pull 모델).
→ 그래서 **문서 3번의 API가 없으면 심사가 시작되지 않습니다.** 가장 급한 항목입니다.

**팀별로 AI 프로세스를 새로 만들지는 않습니다.** API·워커 프로세스는 공유하고,
설정·정책·예산·판례·인덱스를 `teamId`로 분리해 팀별 논리적 에이전트를 구성합니다.
모임 생성 흐름과 준비 상태 제안은 문서 4번을 봐주세요.

## 가장 먼저 답이 필요한 4건

| # | 내용 |
|---|---|
| 1 | **내부 조회 API 8종**을 열어 주세요 (문서 3번에 제안 있음) |
| 2 | AI 심사 API(API-045)가 **접수만 하고 콜백으로 결과를 받는 구조**가 맞는지 |
| 3 | **카테고리 ENUM 9종 확장 — 2026-08-05 확정.** 8/4에는 매핑으로 가기로 했으나, 유형별 카테고리 분리가 어렵다는 판단에 따라 **ENUM에 2종을 더해 9종으로 확장**하는 쪽으로 정리됐습니다. 30종→7종 매핑(문서 6번)은 폐기합니다. 확정 9종: `회의`·`IT_인프라`·`행사_활동`·`장소_대관`·`교육`·`식비`·`교통`·`비품`·`기타` |
| 4 | **팀별 논리적 에이전트 생성 흐름** — API-009 기본 설정·정책 건너뛰기·인덱싱 준비 상태를 문서 4번 제안대로 정리할지 |

나머지 항목은 `풀스택_회신요청.md`에 급한 순서로 정리돼 있습니다
(15번은 화면 대조, 16번은 지출 상세 화면 콜백 정리, 17번은 팀별 논리적 에이전트 계약입니다).
A항목은 실연동을 막는 건이라 우선 회신이 필요하고, 나머지는 구현 순서에 맞춰 협의하면 됩니다.
