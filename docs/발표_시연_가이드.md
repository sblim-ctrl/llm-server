# BudgetOps LLM 팀 — 발표 PPT 내용 · 시연 영상 가이드

> 발표+질의응답 30분(발표·시연 ~20분, Q&A ~10분). 시연 영상 5~7분.
> 이 문서는 발표 자료 제작과 시연 촬영의 대본이다. 실제 PPT·영상 제작은 사람이 진행.

---

## 1. 발표 PPT 구성 (전체 흐름 + LLM 파트 상세)

### 1) 문제 정의 (30초, 공통)
수기 영수증 검토의 수고, 회칙에 있어도 사람마다 다른 판단, 예산 초과를 월말에야 파악.
**반복되는 지출 판단이 담당자 머릿속(암묵지)에만 있다.**

### 2) 서비스 한 줄 + 핵심 기능 3개 (공통)
"모임 지출을 회칙·예산·판례로 AI가 1차 심사하고, 확신 없는 것만 사람에게."
→ 지출 신청/승인 · 예산 관리 · AI 검토.

### 3) 데모 (아래 §2 시연 시나리오와 연결)
청중이 여기서 "무엇을 만들었는지"를 화면으로 이해한다.

### 4) 아키텍처 다이어그램 (공통 1장)
Next.js(프론트) — Spring Boot(백엔드) — MySQL/Redis — **LLM 서버(FastAPI +
LangGraph 워커 + Postgres/pgvector)**. LLM 서버는 비동기 잡(202 접수 → 콜백/폴링)
경계이며, 요청은 5필드만 받고 상세는 서버가 되물어 조회하는 **pull 모델**.

### 5) LLM 파트 기술 상세 (우리 담당 — 슬라이드 4~5장)

- **멀티 에이전트 심사 그래프**
  Intake(영수증 Vision) → 카테고리 자동 분류 → **3심사관 병렬**(회칙 RAG / 예산 계산 /
  판례 검색) → 가드레일 → Adjudicator → 콜백 → 판례 저장.
  화면(AI 심사 결과)에는 증빙 대조(mismatch_gate)를 더해 **4종 심사관 카드
  (증빙·예산·이상탐지·회칙)**로 노출된다.

- **2단계 안전 구조 = 차별점 #1**
  ① 결정적 가드레일(순수 함수, LLM 개입 불가) → ② LLM 합성. 대원칙 "어떤 실패도
  자동 승인으로 가지 않는다." **오승인 0% 하드게이트**로 골든셋 회귀를 강제한다.

- **판례 학습 루프(암묵지 → 형식지) = 차별점 #2 (핵심)**
  escalate → 관리자 결정 → **ADMIN 판례 저장(pgvector 임베딩)** → 유사 지출 자동 판정
  → 같은 패턴 override 3건 이상이면 **회칙 개정안 자동 생성**. AGENT 자기 판례는
  신호로 쓰지 않고(자기오염 방지) ADMIN 판례만 신호로 삼는다.

- **RAG(pgvector)**: 회칙/정책 청크 임베딩 + 판번호 원자적 버전 전환.

- **Generator-Evaluator 패턴(writers 7종)**: 코드가 수치를 집계 → LLM은 문장만 생성
  → 검증기가 수치를 대조(환각 수치 차단).

- **평가 지표 (목 모드 회귀, 실측값)**
  | 지표 | 값 |
  |---|---|
  | 정확도 | **97/97 = 100.0%** (기준 ≥90%) |
  | 오승인(false-approve) | **0건** (하드게이트) |
  | 사용자 노출 금지 용어 위반 | 0건 (하드게이트) |
  | Trajectory(가드레일 발동 일치) | 66/66 = 100% |
  | 판정별 P/R/F1 (승인31·반려22·보류44) | 전부 100% |
  | 에스컬레이션 Recall(놓침 없음) | **100%** (안전 핵심) |
  | 자동 처리율 | 55% |
  | 분류 정확도(관측) | 88/97 = 90.7% |

  골든셋 규모: golden_v1 97건 + 회칙축 5건 + writers 32건. 실모드 100%·LangSmith 트레이싱.

### 6) 트러블슈팅 하이라이트 (LLM 파트 1개)
**"목 임베딩의 한계를 실키로 실증"** — 목 모드 임베딩은 해시 기반이라 의미 유사도가
없어 판례 의미 검색이 성립하지 않는다(거리 0.669~1.151). 실 임베딩(OpenAI)에서만
의미적으로 다른 표현의 유사 판례가 군집(거리 0.236~0.355)됨을 `detect_repeated_overrides`로
실측 — "목으로는 불가함을 증명".
(대안: 예산 부족이 금액·회칙 신호를 이기고 안전 방향(reject)으로 가는 가드레일 우선순위 /
판례 자기오염 루프 방지.)

### 7) 회고 & 향후
DB 영속성(관리형 DB)·HTTPS·비밀 관리·CI 게이트에 LangSmith 편입·참고 코퍼스 확장.

## 2. 시연 영상 시나리오 (대본, 5~7분)

핵심 서사: **"시간이 지나며 지출이 쌓여, 모임의 암묵지를 AI가 형식지(판례)로 전환한다."**
풀스택 사용자 여정 위에 LLM 차별점을 얹는다. 화면·경로·상태값은 최종 화면설계서 기준.

| 시각 | 씬 | 화면·동작 | 나레이션 요지 |
|---|---|---|---|
| 0:00 | 인트로 | — | 수기 검토·애매한 판단·뒤늦은 예산 초과. "판단이 담당자 머릿속에만 있다" |
| 0:30 | 씬1 온보딩 | `/auth/signin` → `/teams` → `/teams/new` → 설정 마법사 `/teams/new/setup`(Step1 회비→Step2 승인정책→Step3 회칙 **🤖 AI 초안**=`POST /api/policies/recommend`) | "모임을 만들면 AI가 회칙 초안까지 만들어준다" (첫 LLM 접점) |
| 1:30 | 씬2 지출 요청 | `/teams/{id}/expenses/new` 제목·금액·발생일 + **영수증 첨부**(카테고리 미입력) → `SUBMITTED` → AI 자동 심사 시작 | "영수증만 올리면 카테고리까지 AI가 채운다" |
| 2:10 | 씬3 자동 승인 | 지출 상세 → AI 심사 결과 상태1 — **심사관 4종 카드(증빙·예산·이상탐지·회칙)** 적합 배지+판정 근거 → AI 최종 승인, 처리 주체 "AI" | "사람이 안 봐도 근거를 대고 통과" (차별점 #1) |
| 3:10 | 씬4 에스컬 | 영수증 금액 불일치 또는 회칙 사전승인 항목 → **⚠ 에스컬레이션**(상태2) → 관리자 승인/반려 → **ADMIN 판례 저장** | "확신 없는 건 사람에게, 그 결정이 판례가 된다" |
| 4:10 | 씬5 판례 학습(단건 인과, **실측**) | **같은 지출**이 판례 저장 전엔 escalate → 관리자 승인(ADMIN 판례 저장) → **동일 지출 재심사 시 이상탐지 심사관이 판례를 인용해 자동 승인**. (프론트에서 실제 영수증 업로드로 진행 → Vision 정상) | "확신 없던 판단이 판례가 되어, 다음엔 자동으로" (정점) |
| 5:20 | 씬6 개정안·예산 | override 3건 → **회칙 개정안 자동 생성** + 모임 관리 `GET budget/ai-insights` AI 추천 + 정산 리포트 CSV | "암묵지가 규칙이 되고, 예산까지 AI가 관리한다" |
| 6:30 | 아웃트로 | — | 차별점 요약: 2단계 안전(오승인 0%) + 판례 학습 루프 |

### 촬영 전 필수 점검
- **심사관 카드 매핑** — 4종 카드(증빙·예산·이상탐지·회칙)가 올바른 소견에 붙는지 실화면 확인
  (인덱스 매핑으로 회칙↔증빙 뒤바뀐 이력 있음). 서버 데이터는 정상.
- **백엔드 BE-009(지출이력) 의존** — 대시보드 AI 요약·정산·예산 AI 추천이 이 API에 의존.
  미구현 시 대시보드 500. 씬3·씬6 경로 동작 여부 사전 확인, 안 되면 로컬 `/ui`로 대체.
- **판례 학습은 단건 인과로 시연**(씬5) — 프론트에서 **실제 영수증 이미지**로 지출을 등록해야
  Vision이 정상 동작한다. seed_demo의 대량 시드는 placeholder URL(`example.com`)이라 실키
  Vision이 못 읽는다(집계 곡선 실측 불가 — 아래 §3). 단건은 실제 이미지라 문제없다.

## 3. 더미데이터 생성 계획

화면설계서 흐름에 맞는 시연 전용 데이터를 구성한다(figma 목업 값에 얽매이지 않는다).

- **기반 자산(재사용)**: `scripts/seed_demo.py`(팀 9001, 4주 WEEK_PLAN — 1주 전부 신규→
  4주 전부 기존), `eval/fixtures/mock_backend.json`(조직·지출 픽스처),
  `eval/golden/receipts/*.png`(합성 영수증), `scripts/seed_reference_corpus.py`(RAG 회칙).
- **씬별 매핑**: 씬1=동아리 유형 PolicyDrafter 초안 / 씬2=`approve` 라벨+일치 영수증 /
  씬3=정상 건(증빙 일치·회칙 적합·예산 충분) / 씬4=영수증 금액 불일치(`mismatch`) 또는
  회칙 애매(`noauto`/`boundary`) / 씬5=`demo_weeks.csv` / 씬6=동일 패턴 ADMIN override 3건.
- **제약**:
  - 목 모드 임베딩은 바이트 동일 요약만 묶임 → 판례 재활용은 **동일 청구 반복** 전제.
    의미적 유사 매칭을 담으려면 **실키 모드(MOCK_LLM=false)** 필요.
  - `DEMO_MONTH="2026-06"` — 시드 판례·지출·픽스처가 같은 달이어야 주간 브리핑 성립.

### 판례 학습 데모 — 단건 인과로 실증 (집계 곡선은 개념도)

- **단건 루프(시연 핵심, 실측 가능)**: 프론트에서 **실제 영수증 이미지**로 지출을 등록 →
  첫 건 escalate → 관리자 승인(ADMIN 판례 저장) → 동일/유사 지출 재등록 → 이상탐지 심사관이
  판례를 인용해 자동 판정. `README` A-9 실키 체크리스트에 실증 기록됨.
- **집계 감소 곡선(개념도)**: `scripts/seed_demo.py`의 주차별 집계는 **현재 실측 불가**다.
  원인 — 목 모드는 rule_auditor가 고정 pass라 **0-0-0-0**(에스컬 자체가 안 생김), 실키 모드는
  지출 영수증이 placeholder URL(`example.com/r/demo-*`, seed_demo.py:100)이라 실 Vision이
  전 건 판독 불가 → **100-100-100-100**(전부 escalate). 두 모드 모두 곡선이 안 나온다.
  → 발표에서는 "판례 축적 → 자동처리율 상승"을 **개념 다이어그램**으로 제시하고, 집계 실측은
  향후 과제(대량 시드에 실제 영수증 이미지 파이프라인 연결)로 명시한다.

| seed_demo 주차별(참고) | 목 모드 | 실키 모드 |
|---|---|---|
| 에스컬 비율(1→4주) | 0% · 0% · 0% · 0% | 100% · 100% · 100% · 100% |
| 원인 | rule_auditor 목 고정 pass | placeholder 영수증 URL 판독 불가 |
