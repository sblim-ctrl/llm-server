## 1. 이번 B-0 리뷰에서 새로 생긴 반영 항목

### 1-1. `GET /v1/jobs/{job_id}`의 `result` — `dead` 케이스 계약 신설 (PR #18 · `5180772`)

`dead`(재시도 소진 최종 실패)일 때 이제 `result`가 채워진다:

```json
{ "error": "<예외 클래스명>", "message": "<관리자에게 보여도 되는 문장>" }
```

후속(같은 브랜치에서 즉시 보완, PR #18 리뷰 코멘트 참고): `message`는 `DocumentParseError` 계열(회칙 파싱 실패)일 때만 원문이고, 그 외 예외는 정형 문구("처리 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.")로 대체된다 — pydantic `ValidationError`나 내부 URL이 노출되는 예외까지 "관리자에게 그대로 보여도 되는 문장"으로 취급하면 안 되기 때문.

**T11에서 확인·반영할 것:**

- [ ] `app/api/jobs.py:18-19` 독스트링이 아직 `succeeded` 케이스만 서술한다 — `dead` 케이스를 추가한 뒤 `dump_openapi.py` 재생성 (독스트링을 먼저 고쳐야 openapi description에 반영된다)
- [ ] `docs/백엔드_요구_내부API_명세.md:156-158`은 "result에 … 문장으로 담깁니다"까지만 있고 **키 이름(`message`)이 없다** — 한 줄 추가
- [ ] xlsx 잡 조회 시트 — `result` 필드 설명에 `dead` 케이스 추가
- [ ] Notion `LLM-API 명세서` — 같은 내용 반영 (B-7/T13에서 이미 손대는 문서이므로 T13이 먼저 반영했으면 중복 작업하지 않는다)
