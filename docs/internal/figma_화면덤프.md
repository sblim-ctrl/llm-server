## 재현 절차

Figma MCP `get_metadata`를 **1회** 호출하면 페이지 전체가 한 번에 나온다.

```
get_metadata(fileKey="aob4NGJ2WiQoxEcFm5nRJ0", nodeId="0:1")
```

응답이 커서(약 380KB) 파일로 저장된다. 파싱 규칙은 두 줄이다.

- 최상위 프레임 = 들여쓰기 2칸의 `<frame id=… name=…>` — 이것이 화면 1장
- 화면 텍스트 = 그 하위의 `<text … name="…">` 의 **name 속성**. Figma는 텍스트 레이어 이름을
  기본적으로 본문 내용으로 잡아주므로 name이 곧 화면 문구다

> **쿼터 주의:** Figma Starter 플랜 + View 시트는 **읽기 도구 월 6회**다. 제약은 "화면 6장"이
> 아니라 **"파일 전체 재동기화 6회/월"** — 위 호출 1번이 26화면을 전부 담아오므로 월 6번까지
> 갱신할 수 있다. REST API 개인 토큰도 같은 한도가 걸리므로 우회 수단이 아니다.

## 한계

- **텍스트만 나온다.** 색·상태(활성/비활성)·컴포넌트 배리언트·인터랙션은 이 덤프에 없다
- 텍스트 레이어를 디자이너가 **수동으로 리네임했다면** name ≠ 실제 문구일 수 있다
- 화면에서 잘리는 긴 문구는 name도 잘려 있다 (아래 `…전` 처럼 끝이 끊긴 항목이 그 경우다)
- `|` 는 이 문서의 구분자다. 원문에 `|` 가 있었다면 구분이 모호해진다
