## 2. 🔴 회의록 안에서 어긋나는 것 두 개

### 2-1. 정산 리포트 AI는 빼는데 대시보드 AI 요약은 만든다?

- 9번: "정산 리포트에서 ai기능 mvp x"
- 5번: "대시보드 AI 요약 메시지 API" 신설

Figma를 보면 **AI 요약 블록은 정산 리포트 화면에 있고 대시보드에는 없다.** 빼는 것과
만드는 것이 같은 기능을 가리키는지, 대시보드로 자리를 옮기는 것인지 확정이 필요하다.

옮기는 것이라면 `report_writer` 대신 `digest_writer`(주간 브리핑)를 쓰는 편이 맞다 —
대시보드는 기간 요약이 아니라 현재 상태를 보여주는 화면이라서다.

### 2-2. `force_escalation_amount`만 설정하면 그 값이 무효가 된다

회의록 2번: "AI 자동승인 한도 - 최소 금액을 특정하여 설정 / force_escalation_amount만
설정하는 것으로"

**어제 실측으로 확인한 문제가 그대로 남는다.** 가드레일에서 두 금액 규칙이 **둘 다
'관리자 확인'으로 귀결**되므로, 실제로 자동/대기를 가르는 것은 항상 작은 쪽이다.

```
자동승인 한도 10만 고정 + 에스컬레이션 기준 50만  →  10만 초과는 전부 대기
에스컬레이션 기준을 50만→100만으로 바꿔도  →  판정 변화 없음
```

Figma 회칙·정책 관리 화면도 `자동 승인 상한액 100,000` / `에스컬레이션 기준액 500,000`
둘 다 있어서 같은 상태다. 재현: `uv run python scripts/wizard_step2_matrix.py`

**셋 중 하나를 골라야 한다.**

1. **입력을 자동승인 한도 하나로** — 코드 변경 0. 화면이 곧 동작과 일치한다.
2. **중간 구간에 별도 동작 정의** — "확신도가 높으면 자동, 아니면 대기" 같은 것.
   다만 이건 §6-1에서 이미 측정했고 **오승인 5건**이 나왔다(정확도 100%→88%).
   머지 게이트를 두 항목 다 위반한다.
3. 두 칸을 유지하되 **에스컬레이션 기준액을 자동승인 한도보다 작게** 쓰는 용도로 재정의.
   직관에 어긋나 권하지 않는다.

**1번을 권한다.**

## 4. 개발자 A 작업 (AI 품질·프롬프트)

| # | 항목 | 근거 | 규모 |
|---|---|---|---|
| 4-1 | **카테고리 직접 입력 삭제 대응** | 회의록 6번 | 중 |
| 4-2 | **OCR 추출값 확장** — 상호명 추가 | 회의록 8번 | 중 |
| 4-3 | 대시보드 AI 요약 API (1-4) | 회의록 5번 | 중 |
| 4-4 | 회칙/정책 제안 API 플로우 (1-5, 7번) | 회의록 7번 | 중 |
| 4-5 | 분류기 잔여 오분류 1건 | A/B 결과 | 소 |
| 4-6 | 골든셋 카테고리 9종 반영 | 통합 후 | 중 |

**4-1이 생각보다 크다.** "사용자가 지출 승인 요청 보낼 때 카테고리 직접 입력 기능 삭제"가
되면 `claim.category`가 항상 비어서 들어온다. 그러면

- `_check_category_mismatch` 경로가 **사실상 죽는다** — 사용자가 고른 값이 없으니 대조할
  대상이 없다. 카테고리 위장으로 회칙 한도를 회피하는 경로도 같이 사라지므로 방어 자체는
  불필요해진다.
- 대신 **AI 분류가 유일한 카테고리 출처**가 된다. 오분류가 곧 통계 오염이라 분류 정확도의
  중요도가 올라간다. 오늘 A/B로 92.9%까지 올렸지만 더 봐야 한다.
- 콜백의 `suggestedCategory`가 '제안'이 아니라 '확정값'이 된다. 백엔드가 이 값을 그대로
  저장하는지 확인 필요.

**4-2 OCR 상호명** — 현재 `ReceiptData.merchant`가 필드만 있고 목에서 `None`이다.
실모드 Vision 프롬프트(`intake`)에서 상호명을 뽑도록 해야 한다. 날짜 정합성 반영은
회의록에 optional로 적혀 있어 뒤로 미룬다. 세부 주문 내역은 우선순위 하.

**4-5** — "배드민턴 셔틀콕 3박스"를 기타로 분류한다(v3·v4 공통). `비품`이 사무용품과
운동용품을 함께 담아 생긴 혼동이다. few_shot 한 건이면 될 것으로 보인다.

## 9. 지금 확인된 것 (배포 자신감)

오늘 실모드 스모크로 확인한 것들이다. `scripts/smoke_real_mode.py`로 언제든 재현된다.

- **확신도가 실제 값** (0.90·0.95) — 목의 0.95 고정이 아니다
- **비용 건당 약 $0.007** — 월 1,000건이면 $7 수준
