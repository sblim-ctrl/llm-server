## 개정 항목 (설계서 섹션별)

### §7.2 API 계약 — 심사 코어 (C2·C3·C6 확정 시)

- **jobId (협의 불요, LLM 내부 조정):** 풀스택 payload에 jobId가 이미 포함(백엔드 발급→콜백 대조)이므로,
  `POST /v1/analyze` 요청에 **`job_id`(백엔드 발급, `expenses.ai_job_id`와 동일)를 수신해 잡 키로 채택**하고
  자체 발급을 중단한다. 202 응답은 접수 확인만. 콜백·`GET /v1/jobs/{job_id}` 키도 이 값으로 통일. 풀스택 액션 없음.
- `POST /v1/analyze`: `team_id` 명칭은 회의 결과에 따라 `organizationId`로 정렬 또는 매핑 명시.
  `callback_url`(요청별 동적 전달) 필드 추가. `심사 목표` 필드는 enum으로 수용(자유 텍스트 거부 — 인젝션 방지).
  claim 미포함 확정 시: payload에서 claim 제거 + 워커 시작 시 지출 상세 조회 API 호출 단계 추가.
- **Agent 승인 API 2종(`/internal/agent/expenses/{id}/approve|reject`) 폐기 후보** (C2 콜백 단일화 시):
  §4.1 그래프의 `execute_decision` 노드는 "백엔드 호출"에서 "콜백 verdict 확정"으로 책임 변경,
  §5.1 툴 `approve_expense`/`reject_expense` 삭제, 멱등성은 콜백 jobId 대조(백엔드)로 이관.
  콜백 응답에 전이 결과(status) 포함을 계약에 명시.
- 콜백: 필드 매핑표(R2)를 §7.2에 표로 수록. `category_assigned`↔`suggestedCategory` 명칭 통일 결과 반영.
  콜백 소견(opinions·reasons·mismatch)의 백엔드 저장처는 `audit_logs` 테이블로 확정(7/16 슬랙, Q2 해결).
- 타임아웃: §8 fail-safe 매트릭스의 "백엔드 측 N분 무응답 감시"를 확정값(협의: 90~120s, 풀스택 초안 30s)으로
  치환 + **늦은 콜백 규칙**(전환 후 도착 콜백은 소견만 저장) 신설.

### §2.1/§5.1 영수증 접근 (C4 확정 시)

- `receipt_signed_url` → **백엔드 영수증 조회 경로 + Agent 토큰** 방식으로 교체.
  `parse_receipt(signed_url)` 툴 시그니처를 `parse_receipt(receipt_ref)`로 변경, GCS 직접 접근 서술 삭제.
  컨테이너 구성도(§2.1)의 `Worker → GCS` 화살표를 `Worker → BE(영수증 프록시)`로 수정.

### §7.3 상태 모델 (C5 확정 시)

- 2축 모델 표기는 유지하되 **와이어 포맷 매핑표**(SUBMITTED/ESCALATED/APPROVED/REJECTED + processed_by)를
  정식 계약으로 추가. ADR-6에 "7/14 풀스택 스키마와의 매핑으로 이행" 각주.

### 신규 §5.4 (가칭) OCR 미리보기 엔드포인트 — 신규 요구 수용

- `POST /ocr/preview`: 프론트 직접 호출(유일한 예외 경로). 인식 결과(금액·날짜·상호·품목)만 반환,
  판단·조직 데이터 접근 없음.
- 인증: 백엔드가 LLM API 키로 서명한 단기 토큰(2분·1회용) 검증 미들웨어 — 토큰 스펙은 Q6 결정 반영.
- 미들웨어 추가: **CORS**(프론트 오리진 한정), 미리보기 전용 레이트리밋(팀 단위가 아닌 토큰/IP 단위).
- 비용 주의: 건당 Vision 2회(미리보기+공식)로 §9 비용 목표(<$0.05/건) 재산정 필요 —
  미리보기는 저해상도/gpt-4o-mini Vision 등 경량화 검토.

### §4.4/§7.2 부가 그래프 인터페이스 (R6 확정 시)

- 대시보드 AI 요약: 백엔드 집계 push 방식이면 `POST /v1/digests/inline`(동기, 집계 데이터 입력형) 신설.
  주간 다이제스트(비동기 잡)는 데모 스코프에 따라 유지/축소.
- 정산 리포트 요약: 동일 패턴 적용 여부 반영.
- `/v1/policy-draft`: teamId 불요(모임 유형 기반) 명시 — 마법사 1단계 호출 가능함을 계약에 기재.

### §3.1/§3.3 가드레일 파라미터 (Q4 확정 시)

- `auto_approve`(마스터 스위치, 기본 OFF) 개념 수용: OFF = 심사·소견 생성은 수행, 자동 실행만 차단
  (전건 ESCALATED) — 기존 `auto_approve_limit=0` 서술을 이 스위치로 대체.
- `force_escalation_amount` ↔ `escalation_threshold` 명칭 정렬. θ(0.8)는 LLM 내부 파라미터로 명시.

### §2.3/§4.4-b 판례 루프 입력 (Q3 — pull 방향 합의 진행 중, 7/16)

- 관리자 결정 수신은 **pull 방식으로 진행** (7/16 슬랙 — 풀스택 선호·LLM 동의, 조회 스펙 확정 대기):
  LLM 워커가 `GET {BE}/internal/agent/decisions?after_id=&limit=`를 60초 주기 커서 폴링,
  결정 id 기준 멱등 upsert 후 임베딩·판례 저장. §7.2 표의 해당 행을 POST→GET(커서 폴링)으로 수정,
  `/v1/precedents` push 대안 표기는 삭제.
- `is_override`·override 사유의 원천 필드(백엔드 스키마) 명시 — 조회 응답 필드로 포함 요청
  (id, expense_id, decision, is_override, override_reason, decided_by, decided_at).

### BudgetAuditor 범위 (Q8 결과에 따라)

- 카테고리별 예산 미제공 확정 시: §3.1 BudgetAuditor 책임에서 "카테고리 한도" 제외, 총예산 잔액·
  사용률·기간 소진율로 축소. REQ-022 카테고리 CRUD 항목은 요구사항 추적표에서 상태 변경.

## llm-server 코드 영향 (계약 확정 후 작업 목록)

| 변경 | 파일 |
|---|---|
| analyze 요청 스키마(job_id·callback_url·dry_run·명칭) | `app/schemas/analyze.py`, `app/api/analyze.py` |
| 영수증 백엔드 프록시 fetch | `app/graphs/review/nodes/intake_receipt.py`, `app/tools/backend_client.py` |
| execute_decision 재설계·approve/reject 툴 정리(목 반환 구표기 `AI_APPROVED` 제거 포함) | `nodes/execute_decision.py`, `backend_client.py` |
| 콜백 스키마 완성(category_assigned·dry_run — 기존 갭) + 매핑 + 메타 실값 | `app/schemas/callback.py`, `nodes/callback.py` (계약 변경 = 풀스택 리뷰 게이트, 업무분장 C5) |
| OCR 미리보기 신규 + 토큰 검증 + CORS + 레이트리밋 | 신규 `app/api/ocr_preview.py`, `app/middleware/` |
| 가드레일 파라미터(auto_approve 스위치) | `nodes/guardrail_gate.py`, `app/schemas/common.py` |
| 관리자 결정 pull 폴링(커서·60초)·판례 멱등 인제스트 (조회 스펙 확정 후) | 워커 폴링 루프 + `app/tools/backend_client.py` |

v1.1 엔드포인트 5종 미구현(B-3·A-7, 구 A3·A6b), `/mcp` 인증 면제. (과제 ID는 업무분장 문서의 담당자 기준 신 체계 — 구 감사 영역 ID 병기)
