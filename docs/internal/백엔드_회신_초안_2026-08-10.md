1. **역방향 토큰** — 공유받은 값을 그대로 `.env`에 적용해 사용 중. 완료.
2. **receiptPath** — 백엔드 확인: 8/6 합의대로 심사 요청(`LLM-003`)의 `receiptPath` 필드로
   계속 전달 중이며, "저희가 상세 응답에서 직접 읽으라"는 뜻이 아니었음. **우리 쪽 코드
   변경 불필요 확정.**
3. **BE-007(멤버명단)** — 백엔드 인지 완료. 우선순위상 추후 구현 예정. 그때까지 실명
   노출·판례 미저장 리스크는 계속 유지(우리 쪽 fail-open 그대로 둠 — 추가 조치 없음).
4. **BE-009(지출이력)** — 백엔드 인지 완료, 곧 구현 예정. 대시보드 요약·예산 추천이
   이것 없이는 안 된다는 것도 백엔드가 직접 재현 확인함. 프론트팀에도 "BE-009 구현
   전까지 AI 요약·예산 카드 에러 가능"을 공유하겠다고 확답.
5. **저희 쪽 주소(`34.50.39.240:8000`)·방화벽** — 백엔드 확인 완료. "이제 실연동
   테스트 진행하겠다"고 밝힘.

## 아직 열려 있는 항목

### ① [종결] 내부 API 401 — 원인은 우리 쪽 낡은 이미지였음 (2026-08-10 해소)

경과: 처음엔 백엔드 쪽(토큰 미반영 또는 nginx 헤더 미전달)으로 추정해 확인 요청을
보냈으나 **오진이었다**. 백엔드가 "내부 API에 재발급 토큰(`a5d17baf…`)을 넣은 것
아니냐"고 되물었고, 기전까지 포함해 그 추측이 맞았다:

- VM 컨테이너가 **토큰 분리(`b67a643`) 이전의 낡은 이미지**로 돌고 있었다 —
  `git pull`은 했지만 반영을 전부 `--force-recreate`(재빌드 없음)로만 해서.
- 구코드에는 `backend_service_token` 필드가 없어 내부 API 호출이
  `SERVICE_TOKEN`(반대 방향 재발급 값)으로 폴백 → 전 구간 401.
- `.env` 값 자체는 정상이었고(`repr` 검사로 숨은 공백까지 배제), 토큰을 직접 박은
  단건 호출이 200인 것으로 외부 경로(nginx)도 정상임을 확인.
- **해결**: `docker compose up -d --build --force-recreate llm-api llm-worker` 후
  계약 검증 **CRITICAL 0건 통과** (남은 실패는 멤버 404 = BE-007 미구현, 예상대로).

→ 백엔드에 정정·완료 메시지 발송 필요 (아래 슬랙 발송용).

### 검증용 지출 ID — 사실상 해소

`team 1 / expense 1` 데이터가 배포 DB에 이미 실재해 계약 검증이 끝까지 통과했다.
백엔드가 의도한 검증용 데이터가 맞는지만 확인받으면 별도 전달은 불필요.

## 별건: 백엔드→LLM 방향 401 (SERVICE_TOKEN) — 2026-08-10, 해소됨

백엔드가 "AI 요약(`POST /v1/dashboard/summary`) 연동 테스트 중 재발급 토큰으로도
401이 난다"고 문의(반대 방향 — ①번 LLM→백엔드 401과는 다른 문제, `SERVICE_TOKEN`
쪽). 우리 쪽에서 재현·진단한 결과:

- VM `.env`의 `SERVICE_TOKEN`이 백엔드에 전달한 재발급 값과 일치 확인.
- 같은 값으로 우리 서버에 직접 `POST /v1/dashboard/summary` 호출 → **422**(인증은
  통과, 빈 본문이라 검증 에러만). **우리 쪽 설정·코드 문제 아님 확정.**
- 진단 명령(컨테이너에 `curl` 없음 — `python:3.12-slim-bookworm` 베이스라 httpx로
  대체):
  ```bash
  docker compose exec llm-api python -c "import os, httpx; \
    r = httpx.post('http://localhost:8000/v1/dashboard/summary', \
    headers={'Authorization': 'Bearer ' + os.environ['SERVICE_TOKEN']}, json={}); \
    print(r.status_code)"
  ```
- 백엔드에 헤더 형식(대소문자·공백·줄바꿈 혼입) 확인 요청 + 재발송 완료. 답변 대기 중.

## 슬랙 발송용 — ① 정정·해소 알림 (발송 대기)

```
401 원인 찾았습니다 — 저희 쪽 문제였습니다. 저희 VM 컨테이너가 옛 이미지로 돌고
있어서(코드는 git pull 했는데 재생성만 하고 재빌드를 안 했습니다), 토큰 분리 이전
구버전 코드가 내부 API 호출에 재발급 토큰을 넣고 있었습니다. 말씀하신 추측이
맞았습니다. 재빌드 후 계약 검증 전부 통과했습니다 — 지출상세·팀설정·예산·이력·
프로필·회칙 정상, 멤버 404는 BE-007 미구현이라 예상대로입니다. 앞서 요청드린
nginx/프록시 확인은 없던 일로 해주세요. 혼선 드려 죄송합니다.

AI 요약 401도 한 번만 다시 시도해봐 주세요 — 이전 시도가 저희 컨테이너
재빌드·재생성 반영 전 시점이었을 수 있습니다. 그래도 401이면 실제 나가는 요청
헤더 캡처(curl -v) 공유 부탁드립니다.

그리고 team 1 / expense 1 데이터가 이미 있어서 그걸로 검증까지 끝났습니다 —
검증용 지출 ID는 따로 안 주셔도 됩니다. (다른 데이터를 의도하셨다면 알려주세요.)
```
