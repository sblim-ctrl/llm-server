## ① 역방향 토큰 — 공유해 주시는 값을 그대로 쓰겠습니다

Agent 토큰(LLM→백엔드 인증)은 제안 주신 대로 **현재 설정하신 값을 그대로 쓰겠습니다**.
값은 **비공개 채널로** 공유 부탁드립니다 — 이 문서를 포함해 어떤 문서에도 값 자체는
남기지 않습니다.

기존에 드린 값은 반대 방향(백엔드→LLM, 저희가 검증)이라 별개입니다 — 같은 값
재사용만 피해 주세요.

---

## ② receiptPath 확인 요청

2026-08-06 합의는 "백엔드가 지출상세 API의 영수증 경로 필드를 심사 요청의
`receiptPath`에 담아 보낸다"였습니다. 이번 회신의 "지출상세 응답의 영수증 경로로
접근"이라는 표현이 혹시 **"저희가 상세 조회 응답에서 직접 읽으라"**는 뜻인지 확인
부탁드립니다.

→ 만약 그렇다면 리스크가 하나 있습니다. 지금 저희 코드(`load_context`)는 지출 상세
응답에서 영수증 경로를 전혀 읽지 않습니다 — 심사 요청의 `receiptPath` 필드만 봅니다.
이 상태로 붙이면 **전 건이 영수증 미첨부로 처리되어 가드레일이 100% 관리자 검토로
넘어갑니다.**

8/6 합의대로 계속 요청 필드에 채워 주시는 것이라면, 저희 쪽 코드 변경은 필요
없습니다. 어느 쪽인지만 알려주세요.

덧붙여, `receiptPath` 값이 절대 URL 형태라면 새 `https://bravobudget.duckdns.org`
기준으로 부탁드립니다 — 구 `http://54.180.206.27` 절대 URL이 오면 저희 쪽 영수증
조회만 구주소·평문으로 나가게 됩니다(상대경로면 해당 없습니다).

## ③ BE-007(멤버명단) — 구현 전까지의 영향 공유

BE-007이 없어도 심사 자체는 막히지 않습니다(저희가 fail-open으로 처리했습니다).
다만 이 API는 **PII 마스킹**과 **판례 저장**에 쓰입니다. 구현 전까지는:

- 팀원 실명이 마스킹 없이 그대로 LLM에 노출됩니다.
- 관리자 결정에 대한 판례가 저장되지 않습니다.

→ 가능하시면 구현을 요청드립니다.

---

## ④ BE-009(지출이력) — 구현 전까지의 영향 공유

BE-009가 구현되기 전까지는 아래 4개 기능이 동작하지 않습니다.

- 대시보드 AI 요약
- 정산 리포트
- 주간 다이제스트
- 예산 배분 제안

**대시보드는 동기 엔드포인트라 프론트에 500을 직접 반환**하므로 영향이 특히 큽니다
(페이지 로드 경로에 걸립니다). 나머지 3개는 잡 큐 경로라 재시도 후 실패 상태로만
남고 화면에 즉시 드러나지는 않습니다.

→ 이 사실을 **프론트 팀에도 함께 알려주시길** 요청드립니다.

---

## ⑤ base URL 수신 확인 — 검증용 지출 ID만 대기 중

HTTPS 전환 재통보 확인했습니다 — base URL은 `https://bravobudget.duckdns.org`로
반영하겠습니다. 도메인이 기존 고정 IP `54.180.206.27`로 resolve되는 것과 인증서
(Let's Encrypt) 정상 여부도 저희 쪽에서 확인했고, 말씀 주신 대로 방화벽 변경은
없습니다. 검증용 팀 ID `1` 확정도 확인했습니다.

→ 남은 것은 **검증용 지출 ID** 하나입니다 — 배포 DB에 데이터 생성 후 전달 주시면
바로 계약 검증을 돌리겠습니다.

## ⑥ 저희 쪽 주소 — 말씀하신 그대로입니다

말씀 주신 대로 저희 LLM 서버는 `34.50.39.240:8000`입니다. 이 주소는 고정(정적) IP로
승격 완료했고, 방화벽도 백엔드 고정 IP `54.180.206.27`만 허용하도록 열어 뒀습니다 —
이제 이 주소로 확정입니다.
