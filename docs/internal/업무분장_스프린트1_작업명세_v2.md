## 재분배 근거 (3차 개정 — 공수·데드라인·포트폴리오 3중 균형 + v1.2 조건부 배정)

2차 개정 후에도 4가지 불균형이 남아 있었다:

1. **공수 격차** — 과제별 중간값을 재합산하면 실제로는 A ≈ 5.5일 vs B ≈ 6.5일(기존 문서의 "B ≈ 6.25일" 표기는 자체 합산 오류)로 약 1.0일 격차.
2. **초반 데드라인 압박** — 개발자 B가 D2 오전에 이중 하드 데드라인(worker 레지스트리 + forecast 머지(C8))을 짊어짐.
3. **포트폴리오 편중** — A가 플랫폼 코어(로더·하네스·LangSmith)와 Vision을 독점, B의 "LLM 플랫폼 코어" 셀은 공란.
4. **v1.2 신규 작업 미배분** — 설계서 v1.2 개정안의 계약 확정 후 작업 6건(~2.5~3.5일)이 분장에 없고, 당시 파일 소유권대로면 그중 4건이 A 소유 파일에 낙하해 확정 시 배분이 다시 틀어질 구조.

3차 개정은 크리티컬 패스 2개(A-1→A-3 하네스, B-1→B-3 예산 버티컬)는 그대로 두고 **주변 과제 3건만 이동**한다 — 2차의 트랙 배치 원칙과 충돌 없음:

| # | 이동 | 방향 | 근거 |
|---|---|---|---|
| 1 | worker.py 레지스트리 리팩터 (~0.25일, BudgetPlanner 과제에서 분리 → **A-2**) | B → A, **D1 머지** | 기계적 리팩터(handle_job if-분기 → dict 레지스트리). A의 D1은 A-1뿐이라 여유. B의 D2 오전은 B-2 단일 데드라인으로 완화. A의 A-4 digest 핸들러가 레지스트리 위에서 작업 |
| 2 | 콜백 계약 (0.5~0.75일 → **A-5**) | B → A | 실질 의존(A-3 하네스의 llm_meta·state.py·load_context.py)이 전부 A 산출물 → A에겐 셀프 조율. 단 **finish_job(cost/tokens) 계측부는 B-7에 흡수**(pool.py·worker.py는 B 유지). C5 diff 예고 의무·콜백 검증 항목도 A로 동반 이동 |
| 3 | LangSmith 코어 배선 (0.5일 → **B-4**) | A → B | B의 "LLM 플랫폼 코어" 공란을 관측 배선 + C9 태깅 형식 **정의**로 채움. B-4 파일(config·worker 기동부·main·.env.example)은 A-3 파일과 무중첩 — 기술 선행 없음. config.py가 B-4·B-7 모두 B가 되어 셀프 조율화 |

**공수(중간값 재합산)**: 개발자 A ≈ 5.9일(범위 5.25~6.5) / 개발자 B ≈ 6.1일(범위 5.5~6.75) — 격차 1.0일 → **~0.25일**. 조건부 트랙 전건 발화 시 A ≈ 7.75 / B ≈ 8.5(§2.5 — 7/16 슬랙 Q3로 추가된 ⑦ pull 폴링을 팀 결정으로 B에 배정, 발화 시점 분산·⑤ 페어 지원으로 상쇄).

| 포트폴리오 축 | 개발자 A | 개발자 B |
|---|---|---|
| LLM 플랫폼 코어 | 프롬프트 버저닝 로더 · 하네스(PII 마스킹/재시도/토큰·비용 계측) | LangSmith 관측 배선 · C9 태깅 체계 정의 |
| 에이전트 버티컬 설계 | DigestWriter 1종 | BudgetPlanner · PolicyDrafter 개정 2종 |
| 멀티모달·벡터 | GPT-4o Vision 영수증 OCR | pgvector 임베딩 군집 탐지(반복 관리자 개입) |
| 신뢰성 엔지니어링 | 콜백 계약·재시도(A-5) · Vision fail-safe 경로 | 고아 잡 회수·크래시 복구(B-7) · 잡 비용 계측(finish_job) |
| 실모드·관측 검증 | review 스모크·마스킹·Digest·Vision·콜백 실측 (A-9) | 자기 그래프 2종·군집·LangSmith 배선·C9 태깅 (B-8) |
| (조건부) v1.2 인터페이스 | 영수증 프록시 · execute_decision 재설계 · 콜백 매핑 · 가드레일 스위치 | analyze 스키마(jobId·callback_url) · OCR 미리보기 보안 미들웨어 · 관리자 결정 pull 폴링·판례 인제스트 |

**부수 효과 — 조율 단순화**: 콜백 계약(A-5)이 A로 가면서 구판의 "사전 합의된 크로스 수정" 2건(load_context.py `started_at`, state.py)이 셀프 수정화되어 소멸. review nodes 소유권 예외(callback·persist_precedent)도 소멸 — A가 review nodes 전부 소유. config.py는 B-4·B-7 모두 B라 완전 셀프화. backend_client.py는 A의 크로스 수정 3건(A-5 재시도·조건부 ②③)이 예상되므로 **단계 이관**(D3까지 B, D4부터 A)으로 1회 핸드오프화. 잔여 크로스 계약은 C8(BurnForecast: B 작성→A 소비)·C3 크로스 수정(test_prompts 2줄)·C10(목 성질)뿐.

**잔여 격차(~0.25일, B 약간 과중) 완화 수단**: ① B-4(LangSmith)는 선행 조건이 없어 D4로 밀 수 있음 ② B-5 few_shot은 각 1개로 최소화 가능 ③ D6 합동 리허설의 C4 연결(신규 그래프 3종 중 2종이 B 작성)은 하네스 소유자인 개발자 A가 페어로 지원.

## 감사 요점 (왜 이 작업들인가)

**잘 구현됨**: 심사 그래프·병렬 fan-out·opinions reducer(§4.1-4.2), 가드레일 6규칙 순수 함수+테스트 13건(§3.3), checkpointer 재개·fail-safe(§8), SKIP LOCKED 워커(ADR-4), 인덱싱 원자 버전 전환(§4.4-a), 판례 루프(§4.4-b), writers 3종 수치 검증(§4.4-c), MCP 읽기 4종(§5.2), 골든셋 30건+오승인 0% 게이트(§9).

**구조적 최대 리스크 — 시스템이 목 모드(MOCK_LLM=true)에서만 완결**:
- 프롬프트 YAML 로더 부재 → 노드가 `system="(prompts/…yaml에서 로드)"` 플레이스홀더 그대로 LLM 호출 (실모드 시 판정 품질 붕괴)
- PIIMasker가 LLM 프롬프트 경로 미연결 (실명 유출, §4.3·§8 위반) / RetryPolicy·embeddings 타임아웃 없음 / LangSmith 미배선
- model·prompt_version·cost·latency가 콜백·판례에 정적값 → §5.3 재현성·§9 지표 무력화
- Intake Vision OCR 미구현 (정규식 텍스트 파서만)

**계약·신뢰성 버그**: 콜백 category_assigned 누락(§7.2 위반)·재시도 없음, 고아 running 잡(워커 크래시 시 영구 심사중), 비-review 잡 dead 시 지출 에스컬레이션 콜백 오발송, `/mcp` 인증 면제, rule_version=1 하드코딩.

**v1.1 미구현**: proposals 테이블(§6), BudgetPlanner(§4.4-d), PolicyDrafter 개정 모드(§4.4-e), DigestWriter(§4.4-c), 엔드포인트 4종.
