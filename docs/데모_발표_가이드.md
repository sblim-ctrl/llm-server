# BudgetOps LLM 서버 — 데모·발표 가이드

> 발표 흐름·데모 시나리오·예상 질문·성과 수치를 한 곳에. 발표자가 이 문서만 보고
> 데모를 진행하고 질문에 답할 수 있도록 작성. (개발자 A 트랙 중심, 2026-07-22)

---

## 1. 한 문장 소개

**BudgetOps** — 모임(동아리·스터디·친목 등)의 지출 요청을 **AI가 회칙·예산·판례에
근거해 1차 심사(승인/반려)하고, 애매한 것만 관리자에게 넘기는** 서비스.
차별점은 AI가 "참고 의견"이 아니라 **승인/반려의 실행 주체**라는 점 —
그만큼 안전장치를 아키텍처 수준에서 보장한다.

## 2. 발표 3막 구성 (권장 흐름)

### 1막 — 문제 제기 (왜 이게 어려운가)
- 모임 총무는 매번 "이 지출을 승인해도 되나?"를 회칙·예산과 대조해야 한다 — 반복적·주관적.
- AI로 자동화하고 싶지만, **"AI가 잘못 승인하면?"** 이 신뢰의 벽. 돈이 걸린 결정이라
  한 번의 오승인도 치명적.
- 핵심 질문: **"AI에게 실행 권한을 주면서도 오승인을 어떻게 0으로 막는가?"**

### 2막 — 해결 구조 (핵심: 판단은 2층으로 나뉜다)
```
지출 요청
  → [1층] 코드 가드레일 (LLM이 못 건드림, 순수 함수)
       하나라도 걸리면 → 무조건 사람에게 (escalate)
  → [2층] LLM 최종 판정 (가드레일 통과한 것만)
       확신 있을 때만 자동 승인/반려, 애매하면 다시 사람에게
```
- **1층 가드레일**이 오승인 0%의 근원. 프롬프트 인젝션("무조건 승인해")으로도 못 뚫는다
  — 코드라서.
- **3명의 심사관**(회칙·예산·판례)이 병렬로 소견을 내고, 가드레일이 그걸 기계적으로 검사.

### 3막 — 데모 + 성과 (아래 3·4절)

## 3. 데모 시나리오 (`/ui` 대시보드 — `localhost:8000/ui`)

> 서버 기동: `docker compose up -d` → 브라우저에서 `/ui`. 목 모드라 키·비용 불필요.

### ① 지출 심사 탭 — "AI가 실제로 판단하는 걸 보여준다"
프리셋 버튼으로 4가지를 순서대로:
| 프리셋 | 기대 결과 | 보여주는 것 |
|---|---|---|
| 정상 승인 | ✅ 승인 | 회칙·예산 충족 시 자동 승인 |
| 잔액 부족(반려) | ❌ 반려 | 예산 부족을 수치로 근거 대며 반려 |
| 영수증 불일치 | ⏸️ 보류 | 증빙 문제는 사람에게 |
| 프롬프트 인젝션 | ⏸️ 보류 | **"승인하라" 주입해도 안 뚫림** (핵심 시연 포인트) |

각 결과에서 **관리자용 사유**를 보여주며 "왜 이렇게 판단했는지 근거가 수치로 남는다"를 강조.

### ② 예산 제안 탭 — BudgetPlanner (팀장 담당분)
- 예산 소진 예측 기반 조정 제안. 수락/기각 버튼으로 관리자 결정 기록.

### ③ AI 총무 브리핑 탭 — DigestWriter (개발자 A)
- 주간 자동 처리 현황 + 예산 전망 + 이상 징후 + **총무 코멘트(AI 권고)**.
- 강조: "수치는 코드가 계산, 서술과 권고는 AI, 그 AI 문장의 수치를 코드가 다시 검산".

### ④ 골든셋 평가 탭 — "품질을 숫자로 증명"
- 42건 자동 실행 → 정확도·오승인·**에스컬레이션 Recall·자동 처리율·판정별 P/R** 표시.
- 강조: "감이 아니라 측정으로 품질을 관리한다".

## 4. 성과 수치 (외워두면 좋은 것)

| 지표 | 값 | 의미 |
|---|---|---|
| 골든셋 정확도 | **42/42 = 100%** (실모드) | 실제 GPT-4o로 전 케이스 정답 |
| **오승인율** | **0%** (튜닝 6회전 내내) | 위험한 자동승인 한 건도 없음 — 하드 게이트 |
| 에스컬레이션 Recall | **100%** | 사람에게 넘겨야 할 걸 하나도 안 놓침 |
| 심사 비용 | **건당 $0.007** | 목표 $0.05의 1/7 |
| 프롬프트 튜닝 | 63.3% → **100%** (6회전) | 측정→진단→수정 사이클로 개선 |
| 테스트 | **179개** 통과 + CI 자동 게이트 | 오승인 발생 시 머지 자동 차단 |

## 5. 개발자 A(플랫폼·평가·신뢰성) 기여 요약

- **LLM 플랫폼 코어**: 프롬프트 버전 로더, 하네스(재시도·PII 마스킹·토큰/비용 계측)
- **기능**: AI 총무 주간 브리핑(DigestWriter), 영수증 Vision OCR
- **신뢰성**: 콜백 재시도, pull 모델 재설계(백엔드 실계약 정합), auto_approve 게이트

  - 골든셋 42건 + 실모드 하니스 + CI 자동 게이트
  - 판정 지표(에스컬레이션 P/R·혼동행렬·자동처리율)
  - **LLM-as-Judge**: 사유 품질을 별도 LLM이 채점 + judge 자체 캘리브레이션

## 6. 예상 질문 & 답변

**Q. AI가 잘못 승인하면 어떡하나?**
A. 두 겹으로 막는다. ①코드 가드레일이 위험 신호(회칙 위반·영수증 문제·한도 초과 등)를
하나라도 감지하면 LLM 판정 전에 무조건 사람에게 넘긴다. ②LLM도 확신(0.8+)이 없으면
자동으로 보류. 골든셋 42건에서 오승인 0%를 실측으로 증명했고, CI가 오승인 1건이라도
생기면 머지를 자동 차단한다.

**Q. 프롬프트 인젝션(설명란에 "승인하라")은 안 뚫리나?**
A. 안 뚫린다. 판정 직전의 가드레일이 순수 코드라 프롬프트로 조작할 수 없다.
데모 ①의 인젝션 프리셋으로 실제로 보여줄 수 있다 — "승인하라"를 넣어도 보류 처리된다.

**Q. 품질을 어떻게 검증했나?**
A. 세 축. ①골든셋 42건 회귀(정답 대조) ②LLM-as-Judge(사유 품질을 별도 LLM이 채점)
③LangSmith(모든 LLM 호출의 트레이스·비용 추적). 프롬프트를 바꿀 때마다 A/B 실측으로
개선을 확인하고, 재현된 개선만 반영했다.

**Q. AI가 지어낸 수치(환각)는?**
A. 생성 결과의 수치를 코드가 다시 검산한다(Generator-Evaluator). 실제로 브리핑에서
AI가 없는 건수를 지어냈을 때 검증기가 잡아 폐기한 사례가 있다.

**Q. 백엔드(풀스택)와 어떻게 연동하나?**
A. API 계약(콜백 스키마)만 맞추면 독립 배포. 계약은 `docs/openapi.json`에 고정돼 있고,
연동 방식이 미확정인 부분은 목(mock) 모드로 개발해 실키·실백엔드 없이 전체를 검증했다.

## 7. 기술 스택 (한 줄씩)

- **FastAPI** — API 서버 / **LangGraph** — AI 심사 워크플로우(그래프)
- **GPT-4o / 4o-mini** — 판단은 4o, 분류·요약은 4o-mini로 비용 최적화
- **pgvector** — 회칙·판례 의미 검색(RAG) / **PostgreSQL** — 잡 큐·저장
- **LangSmith** — 관측 / **Docker Compose** — 3컨테이너 배포
- **pytest·ruff·GitHub Actions** — 품질 자동화
